**Status:** staged, unverified, **Crew RP BLOCKED**, no publication.

## Source-backed mappings

- `PlayerCrewMember.FromJSONDict` (RVA `0x34a3d78`): `cc_contrib` is assigned after `score` to `RP_season`. The existing `crews/viewMembers` decoder supplies member mappings to this native path; actual backend key presence remains unverified.
- `RemoteCrewInfo.FromJSONDict` (RVA `0x34a6cc4`): `cc_rp` maps to `CrewRP_season`, `rp` to `CrewRP_allTime`; `score` supplies an initial fallback. GCC results use this parser, but the signed `viewcrew` contract and active season still require verification.
- `player_rp` corresponds to a profile statistic and cannot stand in for 14-day-season Crew RP. Neither all-time `RP`/`rp` nor generic event leaderboard scores count as seasonal contribution.

## API / staged safety

`CrewMember.season_crew_rp_candidate` / `.season_crew_rp_source` represent the **native-field candidate**, independent of the legacy `crew_rp`, native `rp_all_time`, and `player_rp`. The native key priority is `cc_contrib` before `score`. A malformed present primary key is not replaced by the fallback. Strict nonnegative integer decoding (including zero) rejects booleans, fractional values, numeric overflow, and invalid strings. `score` is only a candidate when it comes from the **crew roster member** parser; not from an arbitrary leaderboard.

`GCCCrewStandings.from_response(json_object)` and `CSR2Services.decode_gcc_crew_standings(json_object)` decode an **already obtained** local GCC crew list (keys `results` / `Results` or `responseData` list), with per-row `cc_rp` candidate, `rp` all-time and `crew_rank`. The actual network URL, season selector, response envelope, pagination, and semantics are not assumed.

## Read-only live check for Priority 1

Install source locally, then use your own authorized session in an interactive terminal:

```console
python -m pip install -e .
python -m csr2cdn.live_validation --execute --crew-only --crew-season-probe --crew-rp-schema
```

`--crew-only` performs only existing allowlisted `crews/checkUserCrew` and `crews/viewMembers` reads. `--crew-season-probe` is opt-in and adds the private aggregate `season_contribution_probe`. Both default and opt-in reports contain only aggregates, never member names/IDs/RP values, credentials or raw responses. `--crew-rp-schema` opts into static field-name counts, including the exact native names `cc_contrib` and `score` when they repeat. Omit `--execute` for zero network traffic.

**Key output fields:** `cc_contrib_present`, `cc_contrib_numeric`, `cc_contrib_null`, `cc_contrib_invalid`, `score_present`, `score_numeric`, `cc_contrib_and_score_present`, `native_season_candidate_numeric`, `distinct_preferred_member_identifiers`, `complete_identity_and_candidate_coverage`. The report sets `active_season_scope_verified`, `in_game_member_equivalence_verified`, and `seasonal_crew_rp_release_unblocked` to false, **even for complete candidate coverage**.
