# Dev28: read-only Crew RP and GCC progress standings

## Evidence and boundaries

An independently run Dev27 sequential read on 2026-10-16 at 13:31:17 UTC returned **29/29** numeric `cc_contrib` member values, summed to **38,226,786**. The exact own-crew-ID-matched GCC progress `score` also returned **38,226,786** and rank **253**, so the observed delta was **0**. The 21 leaderboard rows represented the global top ten and an own-crew neighborhood in that response; they **are not the entire global leaderboard**. Native parser tracing maps `cc_contrib` to `PlayerCrewMember.RP_season` and distinguishes profile `player_rp` and lifetime `RP`.

This evidence supports individual member season contributions, crew-level GCC progress score and backend rank as usable fields **in that tested season**. Neither response carried a verified season ID, active 14-day boundaries, rollover proof, or independent near-simultaneous UI comparison. The sequential reads are not atomic. The GCC progress route is an APK-default path that was successfully read live, but its runtime season-selection configuration has not been established. Do not infer an absolute season number or compute a season index by counting 14 days from an arbitrary date.

## Supported Python surface

- `CrewMember.season_crew_rp`: valid explicit `cc_contrib` only; if absent it is `None` (never profile RP or `score` fallback).
- `GCCProgressCrewScore.crew_leaderboard_score`, `.crew_leaderboard_rank`: explicit aliases for observed GCC progress `score` / `rank`. `crew_id` is retained for exact matching and is hidden from `repr`.
- `CrewRPSnapshot.from_reads(...)`: pure, offline, typed snapshot of *already-decoded* `CrewMembers` and `GCCProgressCrewScores`, matching own crew by exact ID. `.member_rp_total`, `.leaderboard_score`, `.leaderboard_rank`, `.standings` and `.delta` are available. `.public_summary()` omits crew/member IDs and names.
- `CSR2Services.get_crew_rp_snapshot(...)`: one fresh own-crew read, one roster read, one GCC current-progress read, in that order. Requires the normal explicit `allow_network=True` service opt-in; does not write game state, persist a response, or fetch extra pages.

Example (explicit read-only network authorization):

```python
from csr2cdn import CSR2Services

with CSR2Services(PLAYER_ID_FROM_PRIVATE_INPUT, allow_network=True) as service:
    snapshot = service.get_crew_rp_snapshot()
    print(snapshot.public_summary())
    # Advanced consumers may inspect snapshot.standings and member API separately.
```

The CLI remains available for printing the member values and 21 scoreboard rows with explicit consent:

```console
python -m csr2cdn.crew_rp_verification --execute --print-member-values --gcc-live --gcc-print-score-candidates --season-note "Manthey 911 Prestige Cup"
```

No `--expected-members 29` is necessary: when available, the own-crew response's `memberCount` provides the expected occupied count; otherwise a typed warning says the returned roster size cannot be independently confirmed. Optional `--expected-members` overrides the count from the own-crew read.

## Guardrails

- The returned roster supports **1..30 occupied members**, not a hardcoded 29. Require distinct member IDs and numeric explicit `cc_contrib` for each returned row. If server `memberCount` is available, require it to equal the returned row count. If absent, a comparison can be provisional but carries `roster_total_not_independently_confirmed`.
- Require exactly one own-crew ID match; only match exact IDs, never rank, name, position or RP similarity.
- The default maximum read completion separation is **30 seconds** and maximum completed-snapshot age is **300 seconds**. These are **client policy defaults, not server season semantics**. Stale/out-of-order reads remain observable, but suppress `.delta` and `.comparable`. UTC timestamps must be timezone-aware. `now_utc` is injectable in pure offline comparisons.
- A nonzero delta is not automatically corruption: gameplay earns RP between non-atomic calls. No tolerance implies proof of a season or equivalence to game UI. `.active_season_verified=False` and `.atomic=False` are intentionally fixed.
- For callers comparing repeated snapshots, pass `previous=` and optional operator `season_marker=`. A decreased GCC score flags `score_decreased_reset_or_correction_possible`; a changed operator season marker is flagged separately. Decreases might also be recalculations, corrections, or membership changes. **Never automatically label a 14-day rollover or reuse the previous season's score.** No identifier is persisted by this library.
- Do not infer leaderboard pagination from the 21-row response, or make additional guessed GCC requests. Keep the raw member identifiers and auth material out of logs. Printing crew names and scores is intentionally opt-in through the CLI.
