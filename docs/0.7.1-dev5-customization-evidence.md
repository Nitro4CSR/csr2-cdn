# Dev5 — offline APK customization evidence; no invented ID names

## What the actual local CSR2 6.8.0 APK supports

`assets/Media/Metadata/` holds these exact block filenames:

| Block | Bytes | Binary |
| --- | ---: | --- |
| `CarCustomizationParameters` | 556 | `\x00$Nmg` |
| `CarAftermarketCustomisations` | 1,010 | `\x00$Nmg` |
| `CarLiveriesMatrix` | 2,059 | `\x00$Nmg` |
| `CarPresets` | 598 | `\x00$Nmg` |
| `CarAdditionalVisuals` | 218 | `\x00$Nmg` |
| `AftermarketConfig` | 721 | `\x00$Nmg` |
| `HypermodMaterialsConfig` | 475 | `\x00$Nmg` |

Sizes are observations from the local 6.8.0 APK, not global constants. An NMG
binary-to-data or ID-to-label decoder has **not** been established. Source file
presence does not prove that a roster numeric ID has a direct lookup in that
file. Do not attach an in-game name to those IDs without further evidence.

## Offline inspection

`python -m csr2cdn.customization_inventory --apk CSR2_6.8.0.apk` reports
size, sha256 and encoding status for each allowlisted block, and nothing more.
ZIP contents are accessed by exact filename with an 8 MiB per-block limit;
no code execution or network access occurs. This helper never saves APK data.

## Optional normalized candidate manifest

For a *separately decoded and reviewed* source record, an operator may prepare
an explicit JSON manifest of the form:

```json
{
  "format": "csr2cdn.cosmetic-candidates.v1",
  "records": [
    {
      "car_db_name": "MODEL_DB_KEY_FROM_ROSTER",
      "slot": "paint",
      "id": 7,
      "label": "UNVERIFIED_EXAMPLE_LABEL",
      "source_block": "CarCustomizationParameters",
      "source_sha256": "REPLACE_WITH_REAL_64_CHARACTER_LOWERCASE_SHA256",
      "source_record_path": "PATH_FROM_INDEPENDENTLY_DECODED_SOURCE"
    }
  ]
}
```

The example is **not** evidence of a real paint/ID mapping and is intentionally
not used as a bundled fixture. The declared source digest can be validated
against `--cosmetic-apk`; missing or mismatched source hashes fail closed.
Otherwise, this importer makes no assertion beyond the operator's declaration.
`cosmetic_coverage_report` requires exact model/slot/ID agreement and reports
per-slot presence and candidate-match counts; it does not guess unknown IDs.
A digest match proves file identity only, **not source_record_path accuracy or
label semantics**. All returned label candidates have `verified_in_game=False`.

Supported slots include `calliper`, `interior`, `livery`, `livery_zones_set`,
`paint`, `wheel` (string key), and known decal-ID slots. The scope is constrained
to fields already observed in the `crews/viewMembers` response. Display values
require `--show-members`. Private identifiers and raw source payloads are never
persisted or printed by default.

## Bulk-round impact

The previous one-shot four-request test is unchanged. `--cosmetic-manifest-json`
and optional `--cosmetic-apk` consume **local files only**, both in offline
fixtures and a later operator-authorized run. Without a manifest, no label
candidate is returned. In dry-run mode, input paths are not opened. Keep this
feature experimental until an independently decoded mapping and in-game
comparison prove the labels.
