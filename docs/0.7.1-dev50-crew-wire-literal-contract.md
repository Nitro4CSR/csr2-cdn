# Dev50: APK crew-wire spelling and paint-index evidence

This source-only development build follows Dev48/49's ARM64 paint index research. It does not change the production paint decoder, the Trusted/Provisional split, or any vehicle-label mappings.

## Real CSR2 6.8.0 APK observations

- `global-metadata.dat` contains *exact compiled string literal table* entries (each observed once) for `car_paint_id` (literal #29343), `car_interior_id` (#29323), `car_calliper_id` (#29283), and `car_wheel_name` (#29370).
- The compiled `CrewMemberCarInfo` type provides `get_CarPaintIndex`, `set_CarPaintIndex`, `SetPaint`, `get_CarInteriorID`, `get_CarCalliperID`, and `GetCurrentPlayersCurrentCarCrewMemberCarInfo`. It does **not** declare its own explicit `SerializeToJson` or `SerializeFromJson` methods; that absence does not rule out a serializer implemented elsewhere.
- The Dev49 verified `SMPHostInfo` ARM64 JSON path reads/writes its paint *index* at offset `0x68`. No evidence yet connects that SMP-specific serializer to the separate crew-service response.
- Compiled literal existence alone does **not** prove which method uses the literal, nor the semantics of the integer in the crew-service JSON. No vehicle-specific lookup or index-to-ID conversion is performed here.

## Roster comparison (redacted Dev38 report only)

- Database 34011: 29 received paint values, 20 exact paint library ID matches, 9 misses; value `0` appears 8 times and `15` once among misses. These are already available aggregates, not a new game read.
- Value `0` may be shown as **Transparent** by the operator's previously approved *display-only* label. The native paint semantics of `0` are unverified.
- Value `15` remains unassigned: it might be a model-specific paint-list index, but native crew-server encoding and the specific per-car list are not yet proven.

## Work / offline execution

```bash
python -m csr2cdn.dev50_crew_wire_contract \
  --apk CSR2_6.8.0.apk \
  --received-report dev38-received-unmatched-ids.json \
  --output dev50-crew-wire-evidence.json
```

`--received-report` is optional. Supply **only** the already redacted Dev38 report; neither raw saved roster entries nor the private endpoint-cache archive is needed. The output contains compiled literal indices, method-presence flags, binary SHA-256 fingerprints, independent SMP witness booleans and optional aggregate numeric evidence. It contains **no model names, player identifiers or original responses**. Inputs are bounded. It refuses output overwrite.
