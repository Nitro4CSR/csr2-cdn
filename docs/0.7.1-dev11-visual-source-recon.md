# Dev11 — visual Metadata CDN source reconnaissance

## Evidence and nonclaims

The operator confirms that Metadata CDN blocks are refreshed independently
of APK releases, and that visual-code libraries contain human-readable names.
The local APK's bundled `.metadata` files start with NMG binary headers; they
are **not** a known readable JSON shape. No actual JSON response for the
requested visual-code blocks is supplied yet, so this release **does not**
claim a verified visual name/identifier mapping.

This dev build inspects only JSON already held in `MetadataCache` (normally
`<block>.meta` plus `hashes.json`). It does not call `sync()`, issue network
requests, write to a user's game profile, or redistribute game assets.

## Offline workflow

```bash
python -m csr2cdn.visual_source_recon
python -m csr2cdn.visual_source_recon --metadata-cache-dir ./metadata
python -m csr2cdn.visual_source_recon --metadata-cache-dir ./metadata --show-field-names
python -m csr2cdn.visual_source_recon --metadata-cache-dir ./metadata --block CarAdditionalVisuals --show-field-names
```

For a metadata block, `candidate_arrays` means a nested JSON array with
object-like elements. It gives the array length, up to three object samples,
field count and (with opt-in) a schema path and field *types*. These do not
prove a model/car key, cosmetic identifier, or UI name. No source values or
player IDs are included in output. The scanner stops at bounded depth,
row counts, and file sizes, and reports `truncated` if a limit is reached.

`cached_cdn_hash` is the hash recorded by the CDN client; `local_sha256` is a
separate fingerprint of the bytes inspected. A cached hash is not itself a
verification of the file's semantic meaning.

When an actual schema has been independently checked, supply the already
supported explicit `csr2cdn.visual-json-layout.v1` array to decode **only**
that exact named block and map it to a normalized `GameVisualLibrary`. The
inspector can count the result without printing the strings:

```bash
python -m csr2cdn.visual_source_recon --metadata-cache-dir ./metadata --layout-json confirmed-layout.json
```

This does not auto-discover, guess, or generate a layout. A missing/invalid
layout fails closed with a redacted error.

## Bulk test integration

The existing four-read `python -m csr2cdn.crew_bulk_validation` includes a
`visual_source_shapes` section only when a local `--metadata-cache-dir` is
supplied; `--show-metadata-field-names` enables safe key/type signatures.
No extra gameplay or Metadata CDN request is made. To obtain a **current**
cache, sync the relevant metadata blocks separately with explicit authorization,
then inspect their responses offline. The likely candidates include the seven
known customization blocks and `AftermarketCollections`; inspecting them does
not certify that any one contains the visual-code label table.

## Next gate

Obtain a real, current CDN metadata JSON sample or compatible local cache
for the relevant library. Confirm `model_key`, slot/code, and human label
fields against the game's displayed values. Then implement a source-backed
codec and add real-source regression fixtures. Until then,
`car.visuals.paint.name` and similar attributes remain unresolved without
explicit labels provided through `GameVisualLibrary`.
