# Dev23: Native TNR paint, interior and caliper primary records

## Evidence

Source: operator-uploaded `CarTunerStarsPaintLibrary.ASTC.412`,
`CarTunerStarsInteriorLibrary.ASTC.393`, and
`CarTunerStarsCalliperLibrary.ASTC.382` (Android ASTC). All are UnityFS
version 8, serialized with Unity 2021.3.16f1, with readable type-tree
fields. The native internal classes are `TNRCarPaint`, `TNRCarInterior`
and `TNRCarCalliper`, distinct from the standard paint/interior/caliper
records. The files are not included in the Python package.

Their primary arrays carry explicit ID, name (interiors: zone one/two),
and a `Category` string. An `All` category is a global Tuner Stars candidate;
other categories are exact game-model keys such as `Mazda_RX8TNR_2008`.
A small subset is model-specific. The source files also include additional
eligibility/exclusion data which this implementation does **not** decode.
The decoder does not assert it has recovered every auxiliary source record.

| Source | Main-array IDs | TNR name records |
|---|---:|---:|
| CarTunerStarsPaintLibrary.ASTC.412 | 139 | 139 |
| CarTunerStarsInteriorLibrary.ASTC.393 | 47 | 47 |
| CarTunerStarsCalliperLibrary.ASTC.382 | 32 | 32 |

All 218 primary IDs are in a high TNR namespace (>=1,000,000); no ID
collisions occurred when merged with the uploaded standard visual libraries.
These are source-backed **candidate mappings**, not independently validated
roster or UI joins. Only an explicit TNR-model syntax match allows them to
bind to `car.visuals.*.name`, and model-specific rows require exact keys.

## Offline examples

```bash
python -m csr2cdn.visual_library_validation \
  --asset CarTunerStarsPaintLibrary.ASTC.412 \
  --asset CarTunerStarsInteriorLibrary.ASTC.393 \
  --asset CarTunerStarsCalliperLibrary.ASTC.382

python -m csr2cdn.tnr_visual_probe
```

Both commands perform zero network requests. The first reports counts and
source hashes by default, not individual cosmetic names. `--show-examples`
explicitly opts into at most three names per asset.

For a future operator-authorized *narrow* comparison, add the three assets
as `--visual-asset-bundle` inputs to the existing two-request
`csr2cdn.tnr_visual_probe --execute ...` command. That requests only crew
identity and roster. It does not run on import, test, or dry run.

UI accuracy. Do not mark those features as accepted without new evidence.
