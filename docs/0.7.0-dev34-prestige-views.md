# Dev34 — Prestige global display range and crew-filtered event leaderboard

## What the game and live evidence establish

- The authorized Dev32 6.8.0 Prestige read returned **21** entries: the native common range, top 10 entries and five above/below the current player. The UI shows nine racers with rank five, while the bounded response contained only six. Therefore rank-tie expansion **must not be inferred** from the returned ten entries; the server's bounded window can truncate ties.
- The operator reports that the game Prestige UI has **global top 20** and **ten placements either side**, and another **crew filtered** tab displaying racers' placement, name, and time.
- Prestige scores are integer **microseconds**, displayed as seconds with six fractional digits, e.g. `7102993` -> `7.102993 s`; the previous Dev33 formatter remains unchanged.

## CSR2 6.8.0 APK native read trace (offline)

- `EventLeaderboard.GetLeaderboardURL` RVA **0x3389188** selects a string template based on view mode. The binary includes `leaderboard/{0}/scores/crewmembers`, distinct from the event global `leaderboard/{0}/view`, GCC crew-RP `leaderboard/crew-champs-v2/viewcrew`, and friends endpoint.
- `EventLeaderboard.RefreshCrewStandings` RVA **0x33896f0** passes URL-mode **1** and request-range mode **2**. Its range helper RVA **0x2be23a0** takes a common range initialized to `top=10`, `after=5`, `before=5`, `offset=0`, but range-mode 2 replaces **after** and **before** with `30` (ARM64 `movi v0.2s,#0x1e` then store to range offsets +0x14/+0x18). It subsequently calls `PlayerCrewNetwork.FetchEventLeaderboardProgress` RVA **0x35050a4**. That routine serializes `app_ver`, `top`, `after`, `before`, `offset` using **request category 5**. No speculative crew ID parameter is inserted.
- The source code now has `event_crew_standings_contract` as a tightly allowlisted read-only operation. The default `StandingRange.native_event_crew()` is **top 10 / ±30**. The existing general event progress path is unchanged.
- `StandingRange.prestige_ui_window()` explicitly selects **top 20 / ±10** on the existing global `/view` route, matching the *operator-observed UI scope*. These exact global parameters are supported by the native generic range serializer, but **the UI call site selecting top20/±10 was not reconstructed**. Treat this as an unverified, explicitly opt-in candidate until a live check succeeds.

## New library API

- `CSR2Services.prepare_prestige_cup_crew_leaderboard(leaderboard_name=..., ranges=None)`: offline, returns read contract only.
- `CSR2Services.get_prestige_cup_crew_leaderboard(leaderboard_name=..., ranges=None)`: authenticated **separate server-filtered** event crew-tab read; decodes to `LeaderboardPage`. Requires the same operator-resolved Prestige board, not a GCC crew ID. It does **not** filter the global top-ten list locally.
- `CSR2Services.get_current_prestige_cup_crew_leaderboard(season=..., prestige_car_tier=..., prestige_car_key=...)`: resolves event identity using the existing native/metadata selection and preserves its leaderboard offset.
- `csr2cdn.prestige_release_validation`: opt-in `--ui-window` and `--crew-filtered` flags. Can select both in one future authorized read session and print individual name, rank and `time_seconds` by adding `--print-entries`. The summary marks ranks from the crew tab **unverified** (the backend could use crew-local or global placements). It compares overlaps by stable player identifiers and separately counts matching raw scores versus ranks. Names are printed only when asked; PlayerIDs, crew IDs, session data and raw responses are not printed. Unexpected crew-tab response shapes produce a **bounded, allowlisted key/type census**, with no values.

## Offline checks and proposed *later* operator-authorized test

Dry run (zero requests):

```bash
python -m csr2cdn.prestige_release_validation --ui-window --crew-filtered --print-entries
```

When the user explicitly approves the next online round, the combined read would use the previously verified Season 277 board and inputs. *Do not run before approval*:

```bash
python -m csr2cdn.prestige_release_validation --execute --season 277 --car-tier 5 --car-key Porsche_Manthey911GT3RSRewardRecycled_2024 --ui-window --crew-filtered --print-entries --ui-rank 1139 --ui-time 7.102993
```

The `--ui-rank` and `--ui-time` options represent historical operator references, not guaranteed current ranks/times; omit them when stale. The event metadata resolver must confirm that these values still describe the active event. This requests **two separate event leaderboard reads**; `--range-cross-check` adds a third, optional top3+own-player read.

## Remaining acceptance criteria

1. The wider global result shows the expected top 20 and ±10 *entries/placements* according to current game UI; ties may affect count, so do not require exactly 41 rows without observation.
2. The crew-filtered route returns names, ranks and microsecond times for members who raced Prestige. Its ranking semantics (global vs crew-local), own-player visibility and completeness must be checked against the game's separate crew tab.
3. The same event board and event offset are reused. Game/service error response is reported without leaking identifiers or raw JSON. The single-session reads remain non-atomic.
4. CI on Windows, Linux and macOS is **configured, not run**. No 0.7.0 publication until release gates close.

**No live requests or game writes were made while implementing Dev34.** This is a supported, offline-tested read contract and decoder, not a claim that the new backend calls have succeeded.
