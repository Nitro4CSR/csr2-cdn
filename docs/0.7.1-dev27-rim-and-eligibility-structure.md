# Dev27 — offline native rim metadata and TNR category audit

## Inputs and result boundary

This investigation uses **only local package code, synthetic regression assets, and optionally operator-supplied files already on disk**. It performs zero game reads, authentication, CDN requests, or other network access. The supplied Dev26 source archive contains neither the 29-member Dev24 roster nor original `CarTunerStars*` UnityFS files. Therefore Dev27 cannot obtain the **ten unmatched paint entries or one unmatched interior entry's numeric IDs**, and it cannot reproduce the Dev24 live snapshot.

No new cosmetics have been accepted. Published 0.7.0, the native Dev23 TNR decoder, the Dev26 comparison-only ID-overlap loader and the general-production strict loader are unchanged. The normalized rim name decoder is also unchanged.

## Source-level audit additions

### TNR `IncludeToCar` cross-tab

`audit_tnr_eligibility_source()` still requires the complete validated primary TNR array and an independent record traversal. It now emits **counts-only** encoded `IncludeToCar` values split into `All`, model-specific categories matching the already used `is_tnr_model()` *syntax*, and other model-specific categories. The source `Category` key and an `IncludeToCar` integer are observed fields, not verified gameplay eligibility semantics. The bytes after the primary arrays remain uninterpreted. No model keys or row labels are returned.

### Tuner rim compatibility fields

`csr2cdn.dev27_native_wheel_forensics.audit_tuner_rim_source(raw)` validates the **entire** local CarTunerStarsRimLibrary through the canonical decoder, independently locates the validated primary row array, and traverses its `AvailableSizes`, `CompatibleCars`, root `CarNames` and root `DefaultRim` string arrays.

The report gives only aggregate counts: total rim rows, rows with/without explicit CompatibleCars arrays, number of compatibility strings and distinct strings, number coinciding exactly with root CarNames, counts of AvailableSizes entries per rim, root CarNames and DefaultRim sizes, and exact DefaultRim string coincidence with primary rim labels. Strict bounds, expected row IDs/names, intact root trailer and unique array location are required. Corruption fails closed. It deliberately returns **no** rim names, car/model keys, compatible models, asset filenames or per-row data.

Neither `CompatibleCars` nor `DefaultRim` is asserted to define current roster eligibility, and exact string overlap is **not** a proven wheel wire-code join. No universal Tuner rim dictionary is inferred.

### Local asset filename inventory

`audit_wheel_asset_index(database)` provides privacy-safe aggregate candidate counts using the already saved asset index alone. It separates exact `_Wheel` suffixes, `_Wheel_<token>` or `_Wheel.<token>` delimited suffixes, and **non-delimited lookalikes** such as `_Wheelbase`, which a naive prefix scan would include. The model prefix count is a filename heuristic only, not a verified model/roster join; all raw asset names are suppressed.

## Running offline

No local assets at all (prints a no-input report):

```sh
python -m csr2cdn.dev25_visual_forensics
```

With an independently saved local rim bundle and asset index:

```sh
python -m csr2cdn.dev25_visual_forensics \
  --visual-asset-bundle /local/path/CarTunerStarsRimLibrary.ASTC.VERSION \
  --asset-database /local/path/asset-database.json \
  --output /local/path/new-sanitized-report.json
```

The two inputs are independently optional; the local database can now produce an index-only report **without any roster**. Repeated `--visual-asset-bundle` also accepts original standard/TNR paint/interior/caliper sources and keeps the existing source-collision audit. The `--output` file must be a *new* path. The old `--show-unmatched-paint-interior-ids` switch remains opt-in and still requires a previously authorized saved own-crew and roster snapshot; do not fabricate or re-create absent observations.

## Evidence and limitations

- Tests are **synthetic**. No original rim bundle or game roster is bundled. Consequently no real rim compatibility counts or new missing numeric paint/interior IDs were recovered in this environment.
- Existing saved Dev25 audit: primary TNR arrays 139 paint, 47 interior, 32 caliper; IncludeToCar semantics unverified; unparsed post-primary bytes remain unknown. The new category cross-tab cannot be populated for those source files without their bytes.
- Lexical filename patterns, Category syntax and string coincidences are non-authoritative. No automatic labels, car-compatibility rules, color mapping, or wheel mapping are promoted, and nothing is pruned.
- No authenticated request, fetch, mutation, publishing, or third-party installation was performed.

Dev27 remains an offline investigation build, **not a release candidate**.
