# Dev33 — Prestige race-time display and scope

## Operator-confirmed interpretation

The Season 277 Manthey 911 Prestige Cup UI displays server score `7102993`
as `7.102993` seconds; the own-player rank `1139` also matches. A `7014460`
score displays `7.014460` seconds. The same score shared by players yields
same rank, and a fixed-size top-ten-entry server window can expose only some
players tied at the edge: six rank-5 rows were in the 21-entry response, while
the game UI showed nine players tied at rank 5.

## API and CLI

Use `csr2cdn.prestige_time.format_prestige_time(raw_int)` for a fixed six-digit
fraction without floating point. In `prestige_release_validation` output,
`own_player_score` remains the original integer and
`own_player_time_seconds` is a decimal string. `--print-entries` prints each
row with `score_microseconds` and `time_seconds` fields. `--ui-time` accepts
an optional decimal-seconds comparison string, reports a signed difference
in microseconds and seconds, and does not automatically mark the result as
independently UI-verified. `--ui-score` (raw integer µs) remains available.

## Scope boundary

The UI has top 20 global placements, ±10 neighbor placements, and a separate
crew-member tab (placement, name, time). Dev32's native read path requests a
top-10-entry plus ±5 common window. Observing larger UI windows does not
establish their exact signed read contracts or their presence in the existing
response. No new network requests/ranges are invented in Dev33; this work is
presentation and offline testing only. Future work can trace and separately
validate UI-aligned ranges and the crew-only Prestige read.

## Release

Cross-platform CI is configured but still needs to execute. Prestige timing
conversion uses operator UI evidence; all games/boards do not necessarily use
Prestige time units. Nothing is published by this build.
