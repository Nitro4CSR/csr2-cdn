# Dev55 — native paint initialization and asset-source readiness

## Scope

Pinned to CSR2 Android 6.8.0 IL2CPP global metadata and libil2cpp ARM64.
The source inspection uses a previously captured cache, making **zero** server
requests and **zero** crew reads. Production resolvers and trusted labels are
untouched. The previous Transparent interpretation was withdrawn in Dev54.

## Verified in compiled code

`CarVisuals.Setup` has a source-extension switch-like mask `0x604` applied only
after checking the source extension is <= 10. The resulting raw enum values
are **2, 9 and 10**. If that condition fails, a separate branch calls
`eCarSourceExtension.IsIAP`. This is a **code-path distinction**, not a
verified mapping from enum values to vehicle categories. Relevant direct
instructions and conditional targets are verified against the pinned native
method body at RVA `0x380275c`.

One branch checks the sign of the current paint index, tests a candidate visual
paint ID against `0x7fffffff`, checks whether the ID is already in the car-local
list, and may append it. A later branch can update a selected paint index
based on that list's count. Locked aftermarket paint additions discovered in
Dev53 are another input. The full list construction order is not yet known.

## Real cached source inventory

The cached endpoint manifests are checked before reporting metadata or public
asset counts; no private game payloads are opened. The two requested paint
libraries are present, but their global row ordering is **not** evidence of
car-local ordering. `CarSpecificProperties` has 29 registry entries and
`CarAdditionalVisuals` contains one top-level vehicle record. Neither gives
us a verified ordered `CarPaintIDs` array for index 15.

The detector found no assets under its four explicit model-visual filename
patterns, but it is **not an exhaustive asset index search**. Other naming
conventions and uncaptured assets remain possible.

## Remaining evidence to obtain

- Locate the affected car's *source visual-data record* and its initial paint-ID
  field (from the APK's garage car visual-data pointer).
- Understand setup decisions for the applicable source-extension value and
  locked aftermarket entries, preserving their order.
- Compare the constructed car-local list index 15 with an actual source paint
  ID, then use the correct library to label it.

Without these, neither `0` nor `15` has a verified car-local label. Exact
numerical matches against the global cosmetic library are provisional.

## Boundaries

- Does not attempt to emulate all `CarVisuals.Setup` paths.
- Does not read crew/roster/player data, fetch assets, or write to the game.
- Checks supported native bytes fail-closed; refuses cache symlinks, tampered
  manifest-backed inputs and overwriting output.
- The original APK, public-source cache, raw disassembly and all private
  endpoint responses are excluded from distributed artifacts.
