# Dev31 — rim namespace shape evidence and Windows test reliability

## Evidence and limits

The user-supplied Dev30 reports describe a successfully validated public source cache for `6_8_0_Release`, database 33927, with matching index and all four source SHA-256 values against Dev29. The operator made six unauthenticated public-CDN reads for capture and zero for the replay. All three tested rim namespace pairs had zero shared keys under exact, casefold, or punctuation-insensitive comparisons.

The replay counts show 480 rim primary rows, 355 with compatible-car lists, 27 distinct compatible-car strings, 1,716 compatible-car string occurrences, 138 root car-name entries with four duplicate entries, and 134 default-rim string entries. Thus **138 - 4 = 134 distinct root names** and 134 default entries. This is not evidence of a positional pairing, because the schema/semantics are not confirmed and the raw arrays have different lengths. The four original source bundles are **not** present in the source ZIP or this execution environment.

## Additions

`csr2cdn.dev27_native_wheel_forensics.audit_tuner_rim_source()` now includes these additive fields:

- `root_car_names_distinct_count`, `root_defaults_distinct_count`, `root_name_count_minus_defaults_count`, `distinct_root_name_count_equals_default_entry_count`;
- `namespace_string_shape_profiles` for `compatible_cars`, `root_car_names`, and `root_default_rims`, each with bounded counts of exclusive string syntax categories, character-length buckets, and distinct count under different normalization rules;
- `equal_counts_do_not_establish_positional_pairing` and `string_shape_does_not_establish_identifier_namespace`, explicitly keeping these counts untrusted.

The profile outputs **do not include** strings, IDs, hashes of names, positional pairs, model keys or roster responses. The categories are purely lexical (e.g. ASCII-identifier syntax vs. whitespace/punctuation) and do **not** identify Unity field types, game compatibility rules or mapping relationships. The existing source parser and public download budget remain unchanged.

The Windows failure in Dev30 occurred on `Path.symlink_to()` before the intended security assertion could run. Dev31 splits the test: path traversal rejects unconditionally, the `Path.is_symlink()` fail-closed branch is exercised with a mock on every platform, and only the actual symlink-creation integration test skips for known permission or feature-limitation exceptions. Unexpected creation failures still fail.

## Offline replay using already captured original source bundles

```bash
python -m csr2cdn.dev30_public_source_replay \
  --replay-dir ./public-source-cache \
  --baseline-audit public-source-audit.json \
  --output dev31-offline-replay.json
```

This command requires the original **locally cached** source bundles from Dev30 and an unused output filename. It performs **zero** requests and **no** gameplay/roster reads. It will add the new Dev31 fields to the rim audit. The uploaded aggregate JSON reports cannot substitute for raw cache files; no legitimate string syntax profile can be computed from those aggregate JSONs alone.

For tests, run `python -m pytest -q`. The single skip observed on Linux concerns an optional operator asset database not shipped in the source. On Windows without symlink privileges, the actual symlink integration test may also skip; path traversal and mocked symlink defense should still pass. This source bundle has not itself been tested on Windows.

## Trust boundary

Source shape counts and coincident cardinality do not establish a wheel name, a car-to-default relationship, a native wire-wheel decoding, or TNR eligibility. No mappings are promoted, published or pruned, and the historic 10 paint + 1 interior missing roster entries still have no numeric values.
