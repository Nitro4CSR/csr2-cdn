# Dev30 — reproducible public-source evidence, not gameplay mapping

## What prompted this change

The user-supplied Dev29 `public-source-audit.json` reports **six public CDN GETs**, branch `6_8_0_Release`, asset database **33927**, and native validation of **139 TNR paints, 47 interiors, 32 callipers and 480 rims**. That JSON includes aggregate records, library SHA-256 fingerprints and a source-index SHA-256; **it does not include source bytes or vehicle roster values**. Dev30 does not invent these values from counts. The `6_8_0_Release` branch is the verified *reported* branch, not asserted to be the latest game release.

The same report establishes:

- 355 of 480 rims have non-empty `CompatibleCars`; the 1,716 references contain 27 distinct strings.
- **Zero** of those compatible-car occurrences matches the 138 root `CarNames` entries exactly.
- 134 root `DefaultRim` strings do not match any primary `CarRim` name by the existing source audit.
- The root name and default-rim list lengths are **138 and 134**, so a naive index-to-index pairing is not justified.
- `IncludeToCar` on TNR paint/interior records is a still-uninterpreted integer; source `Category` syntax is not a proven compatibility rule.

These are source-evidence facts, not proof of a different game namespace, let alone evidence of a known wheel join. The historical ten paint and one interior unresolved **roster entries** remain unidentifiable without a roster snapshot. No game reads are needed for Dev30.

## New diagnostic — lexical namespace *shapes* (no label disclosure)

An independent parser already validates real source bytes against the canonical `CarTunerStarsRimLibrary` decoder. Dev30 adds **three aggregate lexical comparisons** to that rim audit:

1. `CompatibleCars` strings versus root `CarNames`.
2. Root `DefaultRim` strings versus primary `CarRim` names.
3. `CompatibleCars` strings versus primary rim names (a control to expose accidental collisions).

Each reports the count of shared distinct strings under (a) byte-exact, (b) trimmed casefold, and (c) punctuation-insensitive casefold. The latter two are **many-to-one, lossy transforms** and may produce false coincidences. No matches become vehicle eligibility or roster-wheel names. No source strings, model identifiers or numeric IDs appear in the JSON. Existing exact overlap counters remain unchanged for backward compatibility.

## New controlled public source cache — opt-in only

Unlike the Dev29 validator, whose `--online` path always discards full bundles, this **separate Dev30 CLI** lets a trusted operator explicitly save already validated public-only bundles in a **new local directory**. It never includes proprietary source bytes in a generated source ZIP or sends bytes anywhere beyond the public CDN GET. The callback runs *after* canonical native decoding; cache writes are staged, SHA-256 verified, and published only once all requested source files validate. Never share the saved binary bundles unless you have permission.

Dry-run, 0 requests:

```sh
python -m csr2cdn.dev30_public_source_replay
```

Opt-in capture of the previously verified 6.8.0 source set (maximum six GETs), to a directory that **must not exist yet**:

```sh
python -m csr2cdn.dev30_public_source_replay --online \
  --branch 6_8_0_Release \
  --slot paint --slot interior --slot calliper --slot rim \
  --save-dir ./public-6_8_0-source-cache \
  --output dev30-online-report.json
```

Then zero-network replay as many times as needed, optionally comparing hashes to the **user-supplied** Dev29 audit:

```sh
python -m csr2cdn.dev30_public_source_replay \
  --replay-dir ./public-6_8_0-source-cache \
  --baseline-audit ./public-source-audit.json \
  --output dev30-offline-replay.json
```

Only the four fixed, hardcoded source asset names can be cached or loaded; no arbitrary CDN URLs or file paths can appear in a cache manifest. Symlinks, invalid source sizes, hash mismatches, corrupt bundles and unrecognized source structures fail closed. User environment proxies and `.netrc` are ignored for CDN GETs (`session.trust_env = False`). The official native decoder, strict library loader, production mappings, gameplay probes and player privacy defaults are unchanged. Cache directories contain full public game assets locally, so keep them private by default and do **not** embed or redistribute them in a source archive.

## Verification and limits

The new cache/replay and namespace tests use **synthetic** UnityFS assets and mocked CDN responses. The local development environment could not resolve the public CDN hostname, so **no Dev30 real CDN result is claimed**. The user-provided Dev29 audit **is** evidence of the separate successful remote validation, but cannot substitute for the four source binaries. The offline replay will only produce meaningful **real** casefold/punctuation intersection counts after a network-enabled operator captures the source assets once. A hash match to Dev29 shows the same source bytes, not verified semantics.

**Do not publish labels, compatibility or wheel mappings based solely on these diagnostics.** Dev30 is a diagnostic investigation release only.
