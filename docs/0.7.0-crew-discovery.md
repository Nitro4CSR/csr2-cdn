# 0.7.0.dev3: automatic own-crew discovery

## Problem

Players generally know their **PlayerID**, not their numeric/string crew UID.
The previous dev2 live runner silently skipped crew checks unless `--crew-uid`
was provided. A public crew-read API must not require manually reverse-engineering
that identifier.

## Offline reconstruction from CSR2 6.8.0

- `PlayerCrewNetwork.CheckUserCrew` (RVA `0x34ffd64`) constructs the **read**
  `crews/checkUserCrew` with `app_ver` and request category 3.
- `CheckUserCrewResponse` (IL2CPP type 2056) declares `playerUID`, `crewUID`,
  `crewName`, `memberCount`, `playerRole` and other attributes.
- `PlayerCrewNetwork.FetchCrewMembers` (RVA `0x350203c`) sends the read
  `crews/viewMembers`, including `crew_uid` and `app_ver`, category 3.
- The own-crew response is the **authoritative identifier source** for the
  second request. The library never treats the PlayerID as crew UID, scans
  an unrelated crew list, or downloads a save file.

These client-side contracts have not yet been validated against a live reply.
The default decoder rejects responses missing recognizable membership fields,
and validates a returned UID before interpolating it into a subsequent read.
It treats a recognized response with an empty `crewUID` as no resolved crew;
negative membership semantics still require a live check.

## Python interface

```python
from csr2cdn import CSR2Services

with CSR2Services("YOUR_PLAYER_ID", allow_network=True) as services:
    own = services.get_my_crew()
    if own.in_crew:
        roster = services.get_crew_members()    # no crewUID needed
```

`get_crew_members()` automatically runs `get_my_crew()` if necessary. The
membership lookup is cached **in memory for up to five minutes**. To force a
new lookup if the player changed crews:

```python
roster = services.get_crew_members(refresh_crew=True)
```

The existing advanced API remains available:

```python
roster = services.get_crew_members("EXPLICIT_CREW_UID")
```

`prepare_my_crew()` previews the discovery request offline. In contrast,
`prepare_crew_members()` without an explicit UID requires a previously cached
own-crew response and intentionally never attempts implicit network I/O.

## CLI and live preflight

```shell
csr2cdn services crew                               # offline preview
csr2cdn services --execute crew                     # hidden PlayerID prompt, live
python -m csr2cdn.live_validation --execute         # attempts crew automatically
python -m csr2cdn.live_validation --execute --skip-crew
```

Do not supply `--zid` in a shared shell, because command-line arguments may be
visible in terminal history/process listings; the interactive prompt avoids
that exposure. The live-validation runner only reports status and member
counts. It does not emit private player records, request internals or session
information. No save-game downloader, save uploader or global chat API is
included.

## Remaining validation

Only offline synthetic-response tests have passed. An authorized account that
is currently in a crew must confirm membership lookup, list retrieval, and
returned member/car schema. An account with no active crew should be tested
separately. Do not mark the release gate complete solely because metadata
access succeeded.
