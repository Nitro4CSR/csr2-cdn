# Dev26 — offline source-only ambiguity guard

## Findings established without game access

This is a source-code-only continuation of Dev25. The uploaded Dev25 ZIP includes
Python source, test fixtures containing synthetic data and source documentation.
It **does not include** the previously queried 29-member roster or the game
UnityFS ASTC bundles. The separate `dev25-source-audit.json` is a summary, not a
reverse-encodable store of individual IDs. Therefore **none** of the ten missing
paint IDs or the single missing interior ID can be computed from the uploaded
materials. Do not manufacture values based on known library ID ranges.

The submitted Dev25 source audit established primary TNR arrays with 139 paints,
47 interiors and 32 calipers. It counted model-specific Category records (25
paints, six interiors, zero calipers) and reported uninterpreted bytes after
primary arrays (88,680 paint, 9,932 interior, 427 caliper). These bytes are
**uninterpreted**; they do not establish additional mappings, compatibility
semantics or any valid way to identify roster values. `IncludeToCar` values
remain integer observations, not eligibility rules.

Dev25 has `assess_tnr_resolution_comparison()` which explicitly counts numeric
IDs present in both standard and TNR sources as **ambiguous**. However the
production loader `visual_library_bundle.load_visual_libraries_unityfs()`
rejects any duplicate per `(slot, code)` before comparison begins. Dev26 adds
an alternate loader **inside `csr2cdn.dev25_visual_forensics` only** that
preserves overlap for the exact declared standard/TNR source pairs. This fixes
that potential forensic blind spot without weakening the production loader.

## New output from the existing offline CLI

`python -m csr2cdn.dev25_visual_forensics --visual-asset-bundle /path/to/CarTunerStarsPaintLibrary.ASTC.412`

When native local sources are supplied, the CLI now includes `source_catalog`:
source names, record counts and counts of duplicated IDs in each available
standard/TNR paint/interior/caliper pair. It does **not** print ID values,
cosmetic names, model keys, wheel strings or player information. A duplicate
remains unresolved in source-scoped comparison. The returned combined catalog
must not be passed to general-purpose label resolution; `match()` would not
know which source to choose.

No native game data is included in this package. A plain CLI call without
local files gives the same no-input report, and the uploaded TNR aggregate
audit still cannot supply missing values. For wheels, model asset code prefix
checks and standalone TNR rim source names remain independent indicators only.
The original `CompatibleCars` field is skipped by the normalized rim label
parser, not evidence of a roster wheel-string join. No color joins were added.

## Invariants and validation

- No changes to `visual_library_bundle.py`, Dev23 TNR decoder, standard visual
  label resolution, Dev24 probe, game services, or HTTP infrastructure.
- Only declared standard/TNR source-pair duplicates can survive inside the
  offline-only forensic loader. Duplicate inputs and unrelated collisions fail.
- Other fields and unverifiable labels remain untrusted; no mappings or
  assets are deleted or promoted.
- Tests use synthetic UnityFS files, fake source records and synthetic crew
  fixtures. No authenticated requests, live reads, CDN calls or downloads.
- The Dev24 snapshot cannot be reconstructed from the package.

This is investigation tooling and is **not** a release candidate.
