# 0.7.0.dev13 — Native Prestige group identity preflight

**Not final-release evidence.** The dev12 live report loaded all configured metadata sources but found no `Silver_Prestige` groups in its extracted, *named* race-group collection. No Prestige standings query was sent. This does not prove the event is absent.

## Native evidence revisited

- `RaceEventData.IsPrestigeEvent` at RVA `0x32d8d40` calls `RaceEventGroup.get_TelemGroupName` (`0x32fb140`), then compares with `Silver_Prestige`. The direct native call sites found in this APK belong to the map/event-selection UI; this predicate does **not** itself load or generate a race group.
- `RaceEventGroup.get_TelemGroupName` returns the serialized group's telemetry field. IL2CPP type `RaceEventGroup_JsonData` has distinct fields `id`, `EventGroupName`, `TelemGroupName`, `RaceEvents`, `Leaderboard`, and `ScheduleID`. `EventGroupName` is not the only native group identity field.
- Before dev13, the type-47 Unity decoder kept a group in `RaceEventGroups` only if `EventGroupName` was a nonempty string, silently dropping an otherwise complete group that supplied `id` and native Prestige telemetry but no UI name.

## Changes, without inventing a board

- Decode and retain independent `PrestigeRaceEventGroups` from Unity TextAsset JSON or MonoBehaviour type trees when a record has exact native `Silver_Prestige` telemetry, serialized `id`/`EventGroupName`, and actual `RaceEvents`. They are preserved even with no display name and are not merged into the Showdown event list.
- Merge these as `_RuntimePrestigeGroups` and let the Prestige-specific scanner consume them. Identity is taken from explicit serialized `id` or `EventGroupName`. The existing schedule/first-event/leaderboard-template/ranking requirements still apply. No placeholder name, ID or timestamp is constructed.
- Extend the sanitized report with `runtime_prestige_groups` and `unnamed_runtime_prestige_groups` counts. Do not print token material, native session data, event records, player IDs or rankings.

## Scope and next evidence

All tests are offline and use synthetic records. Dev13 cannot establish whether the current production Prestige event was hidden by this exact decoder filter. If the new counts are still zero, the remaining issue is earlier: event generation, missing/stripped metadata, or the source-category selection. Investigate the game's event loading chain and classified in-game event rather than asserting the cup is inactive. An authenticated Prestige standings read remains required before 0.7.0 final.
