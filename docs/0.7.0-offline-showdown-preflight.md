# 0.7.0 offline Showdown preflight (dev1)

**Status:** Tested offline with synthetic fixtures. No game-server calls were
made. These tests cannot establish which Showdown is active on October 15,
2026: only `FeatureKillswitches.meta` was supplied, not a fresh
`ShowdownEventsContainer`, `EventSchedule`, or `EventLeaderboards` snapshot.

## Discovery flow

The CSR2 6.8.0 native metadata defines `ShowdownEventsContainer.RaceEventGroups`
and `EventSchedule.ScheduleList`; `EventLeaderboards` contains leaderboard
definitions. The package accepts those metadata blocks as JSON fixtures.

1. Parse Showdown groups and link to a named schedule without inventing a match.
2. Check the time window and report `scheduled_now`, `upcoming`, `elapsed`, or
   `unknown`. A time window is not proof of player-specific eligibility,
   segmentation or backend availability.
3. Only permit an offline request preview if the source explicitly provides a
   complete, resolved leaderboard name. Template IDs and event IDs are **not**
   substituted. The template ID and any explicit group identifier are exposed
   separately for future native-derivation work. The game may calculate these names at runtime, in which case
   this preflight reports the unresolved dependency.
4. Build the read-only request. No network access is needed until the final
   authorized test phase.

## Offline commands

Keep local snapshots named `ShowdownEventsContainer.meta`,
`EventSchedule.meta`, and optionally `EventLeaderboards.meta` in one folder.
`EventSchedule` is needed for a time-status classification.

```console
csr2cdn services --metadata-dir ./meta showdowns
csr2cdn services --metadata-dir ./meta showdowns --scheduled-now
csr2cdn services --metadata-dir ./meta showdown --current
```

For repeatable tests, pass `--at 2026-10-15T12:00:00+00:00` **before** the
subcommand. This is a synthetic timestamp used for fixture tests, not a claim
about the game's current schedule.

```python
from csr2cdn import CSR2Services, ShowdownDiscovery

source = ShowdownDiscovery.from_json_directory("./meta")
current = source.scheduled_now()   # time-only preflight
with CSR2Services("YOUR_PLAYER_ID") as client:
    if len(current) == 1 and current[0].requestable:
        contract = client.prepare_current_showdown(source)
        print(contract.route, contract.params)
```

At the final test phase, the existing `MetadataClient` can provide fresh blocks
using the user's PlayerID. The discovery adapter accepts this client via
`ShowdownDiscovery.from_metadata(...)`, preserving refresh and avoiding
bundled event or leaderboard lists. Fetching metadata is a network operation;
**it was not performed for these tests**.

## Offline acceptance checks

- Request previews never invoke HTTP; local metadata and response decoders
  are tested with synthetic fixtures and mocked sessions.
- Missing timestamps, incomplete metadata, unknown board identities, and
  multiple simultaneous Showdowns do not silently yield invented IDs.
- The package never retrieves chat messages, save data, or modifies game state.
- Showdown Leagues APIs remain present for compatibility, but it is currently
  a discontinued in-game mode.
- Session and transport errors print no authentication details, raw responses,
  account identifiers, or secrets. This is a logging guarantee, **not** a claim
  that authentication code in a distributed Python library is uninspectable.

## Still blocked before a final release

The exact derived leaderboard name for generic Showdown and Prestige Cup is
not guaranteed to be present in source metadata. The APK constructs some IDs
from player/event metadata and time-specific values. Real current-event
snapshots and final authorized service calls are required to confirm the
complete mapping, score model, response decoding, and event availability.
This is why the package remains a development prerelease rather than 0.7.0.
