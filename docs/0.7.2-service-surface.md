# Production service surface — coverage inventory

Source of truth: IL2CPP `global-metadata.dat` from `CSR2_6_8_0.apk`
(sha256 `22d08a5ed2ebafc2…`, metadata v31, 44,500 string literals, 183,707
identifiers). Route names come from string literals and from `const string`
field defaults in the `fieldDefaultValues` blob, which bind a route to its
owning class. Request shapes come from method parameter names; response shapes
from the declared fields of the `*Response` types. No route was called against
a live account to produce this document.

118 game-service routes exist. The package addresses **7 read contracts over 6
distinct routes**, plus the CDN/metadata and portal surfaces which are not
part of this table.

## 2. Open — reads

### 2.1 The `tournament` block is the Collections Tournament (corrected 2026-11-15)

`CheckUserCrewResponse.TournamentCrewData` is the live `tournament` key. The
6.8.0 client parses it with `CollectionsTournamentCrewData.FromJson`
(`events`/`meta`) and each event with `CollectionsTournamentCrewEventData.FromJson`
(`crews`/`hash`/`members`/`vanity_reward`). It is the crew-against-crew
Collections Tournament (three crews per group, three days of two time trials,
every fourteen days on `TOURNAMENT_SEASONAL`), already decoded by
`crew_optional_data.CrewTournament`. Event ids are tournament ids, `hash` is
the group id, and a closed event's tier is the crew's placing (279 closed at 2).

The 2026-11-06 entry here called it the Grand Crew Championship matchup block
and declared the cup standing absent; both were wrong. `crewLeaderboardType`
has still not been seen on the wire. The decoder added for the misread
(`CollectionsCupCrewStanding`) has been removed.

## 4. Non-route open items

- **`_service_rejected` ignored snake_case `error_code`. Fixed.** It checked
  only `errorCode`, but every live 6.8.0 reply spells it `error_code`. Until
  this was corrected an error envelope — including the cup leaderboard's 403 —
  passed through every decoder in `service_models` as a successful result.
  `OwnCrew.from_response` now matches the crewless answer (itself an
  `error_code: 306` envelope) before the envelope check.
- **`_research/dev47_apk_paint_semantics.py` reads `field_count` at offset 0x42.**
  In IL2CPP v31 that is `property_count`; `field_count` is at **0x44**. The
  module still finds the fields it looks for because those classes have enough
  properties to cover the range, but it reports zero fields for any class
  without properties. Latent, worth fixing.
- **`WinsRequired` on the weekly collections cup ladders most likely counts
  races.** The ladders `[3,8,14,22,32,44]` / `[5,13,23,35,50,68]` top out at
  exactly each week's race count. That is an inference from the numbers; the
  time-trial mechanics once cited for it belong to the tournament, not the
  ladder. Docstrings now say so.
- **`ReadContract.request_type` numbering, probably resolved.**
  `EWebRequestType` declares `Default, Account, RTW, Crew, Events,
  ZyngaAccount, …`. Sequential ordinals put `Crew` at 3, matching the working
  `checkUserCrew` and GCC values, and `ZyngaAccount` at 5, matching the
  leaderboard reads — which fits, since the leaderboard is a Zynga platform
  service with its own auth. `Events` at 4 is then used by the single
  `events/` route. Nothing dispatches on the field, so it is documentary
  either way; the enum's explicit values did not decode from the
  default-value blob, so this remains a reading rather than a proof.
- `csr2tt.core.nmgx.co.uk/twitch` time service call shape (bare GET returns
  HTTP 240 empty).
- The portal advertises 6 URLs; the package uses 1. `metadata_php8` is
  identical; `metrics`, `new_metrics`, `logging` are write sinks.
- 13 portal switches, incl. `MinimumSupportedVersion: 6.8.0` and
  `NewMinimumSupportedVersion` — server-published version signals relevant to
  branch discovery.
- `libRakNet.so` / `csr2-prod-showdown.raknet.csr2.zynga.com` — a non-HTTP
  transport, entirely unmapped.
