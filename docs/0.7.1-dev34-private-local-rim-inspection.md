# Dev34 — explicit local-only native rim field inspection

## Why this exists

Dev30's real public-source report established 480 Tuner Stars rim records, 27 distinct `CompatibleCars` strings, 138 root `CarNames` entries (four duplicated entries), and 134 root `DefaultRim` entries. Exact, case-insensitive and punctuation-insensitive comparisons among the three string namespaces found **zero** matches. Dev32 and Dev33 introduced aggregate relationship checks, but their reports intentionally do not include the original strings, so they cannot answer *what these different names actually look like*.

Dev34 adds a **separate opt-in private output** to inspect the canonical native fields from the already-cached `CarTunerStarsRimLibrary.ASTC`. This does not contact a server, require a game login, fetch a roster or change any production mapping. There is **no need to repeat the CDN capture** if the validated cache is still present.

## Run (existing cache, zero network)

```shell
python -m csr2cdn.dev30_public_source_replay \
  --replay-dir ./public-source-cache \
  --baseline-audit public-source-audit.json \
  --output dev34-offline-replay.json \
  --private-rim-fields-output ./dev34-private-rim-fields.json
```

Both output paths must be **new**. `dev34-offline-replay.json` remains privacy-safe and counts-only. **The private file contains original public game-source strings, and may contain publisher-proprietary naming conventions. Keep it local, don't publish or attach it to public issues.** It is created with restrictive `0600` file permissions on POSIX systems (Windows permissions depend on the host filesystem and account). The command prints only the redacted replay JSON to stdout and does not print the private file location or contents. The original cached ASTC bytes are *not* copied into either report.

The opt-in private file contains:

- One primary source record for each decoded rim, with its source **rim** numeric ID, rim name, `BrandName`, `Category`, the exact ordered `CompatibleCars` string array, and the declared `AvailableSizes` **entry count** (not inferred units).
- The separate ordered root `CarNames` and `DefaultRim` arrays, **not** a fabricated positional pairing.
- SHA-256 of the source bytes, scope/trust warnings and explicit flags that native source IDs are not the missing roster paint/interior IDs.

The output is written only **after** the regular manifest integrity and native structural replay has succeeded, and after a second rim source SHA check. No cache modification, file overwrite or implicit raw-string export is permitted. `--private-rim-fields-output` is accepted only with `--replay-dir`, never online mode or dry-run.

## Validation and limitations

The local suite uses synthetic native UnityFS assets and controlled fake HTTP sessions. No original four ASTC bundles were available in this development environment, so **no real-source private inspection was performed here**. All previously reported rim namespace discrepancies remain sourced from the operator's Dev30 reports. Matching or visually similar source names remain clues, not verified roster wheel strings or eligibility. Source rim numeric IDs do not reveal the historical ten missing paint and one missing interior roster entries.

The normal replay, canonical decoder, strict production loaders and all mapping trust gates are unchanged. Dev34 remains an investigation build, not a release candidate.
