# Dev29 — bounded public CDN source verification (no gameplay)

## Goal and evidence boundary

Dev29 allows **optional** public asset-CDN reads to validate original source libraries in a network-enabled environment, without making game account requests or requiring a player/crew ID. This implements the updated workflow: source-code analysis, automated package tests, and limited CDN validation; visual in-game comparisons only when source/HTTP evidence is insufficient. No cosmetics become trusted from a successful CDN download. There is **no** roster input and therefore no way to recover the eleven historical unresolved paint/interior *entries'* numeric IDs from this command.

The existing Dev23 TNR decoder, standard-vs-TNR comparison, strict source loader, Dev25 gap diagnostics and Dev28 structural screens remain unchanged. This command is **separate** from game/HUB/metadata services, with no login or write operations.

## Network boundary

`python -m csr2cdn.dev29_public_cdn_forensics` defaults to an offline dry-run (`network_requests: 0`). A real request requires both `--online` and a caller-supplied release branch. The command **does not** automatically search store versions, guess release branches, retry, or discover players. It does only these public HTTPS GETs on the hardcoded `https://csr2.cdn.zynga.com` origin:

1. `asset_database_<explicit_branch>.version` (maximum 128 KiB)
2. `asset_database.<returned_numeric_version>.json` (maximum 32 MiB)
3. Optionally, up to **four** exact `ANDROID/ASTC/CarTunerStars{Paint,Interior,Calliper,Rim}Library.ASTC.<version>` bundles, and only when the public asset index gives a valid version and advertised positive size under 8 MiB.

A typical index-only online run uses **2 GETs**; four selected source bundles require at most **6 GETs** total. Reads reject redirects and enforce streaming byte limits, expected bundle sizes, canonical source decoder validation, and independent source audit. No cache or raw bundles are saved. The report includes SHA-256 fingerprints of the **public index and validated whole bundles** for reproducibility, never IDs or labels. The only optional file export is a sanitized aggregate JSON report, written with exclusive create so an existing file is never overwritten.

The command creates a new empty Requests session only after explicit opt-in, with ambient `.netrc` credentials and proxy authentication disabled. Network failure, timeout, 404, oversized content, unsupported native structure, or version disagreements fail closed. If a bundle is missing from the index, the slot is reported unavailable and **no speculative URL is contacted**. A successful download verifies a source file against the parser, *not* the visual appearance in-game, TNR applicability, a wheel roster join or color join.

## Usage in a network-enabled terminal / Work cloud computer

Dry-run (safe anywhere):

```sh
python -m csr2cdn.dev29_public_cdn_forensics --slot paint --slot interior --slot calliper --slot rim
```

Index only — no game account:

```sh
python -m csr2cdn.dev29_public_cdn_forensics --online --branch <EXPLICIT_KNOWN_RELEASE_BRANCH>
```

Source validation (exact current branch must be established independently):

```sh
python -m csr2cdn.dev29_public_cdn_forensics \
  --online --branch <EXPLICIT_KNOWN_RELEASE_BRANCH> \
  --slot paint --slot interior --slot calliper --slot rim \
  --output public-source-audit.json
```

The angle-bracket token is an instructional placeholder, **not** a branch that Dev29 discovers. Do not pass secrets or account credentials. Each run creates at most the specified number of GETs. To run with a supplied source ZIP in Work, extract the ZIP, install the package, run the tests, then run the command in a network-enabled session if the public CDN is reachable; return the sanitized JSON only. Work cloud access is dependent on the host environment.

## Findings in the original development environment

- Synthetic request/response regression tests exercise the full index/asset/decoder path, size caps, redirects, unexpected hosts, absent assets and corrupt UnityFS bundles. No fake HTTP response is described as a real server response.
- An attempt to reach a public CDN `.version` URL from this execution environment failed at **DNS resolution**, before any HTTP response could be received. The browsing fetch interface also could not access it. Accordingly **no live CDN validation completed here**. This reflects the *execution environment*, not proof that the server is down.
- The source ZIP contains no original proprietary assets, roster snapshot, private fixtures, player identifiers or auth credentials.
- No TNR labels, wheel joins, color joins or eligibility rules are promoted. The Dev24 count of ten paint entries plus one interior entry remains historical and **not re-measured**.

Dev29 is an investigation build, not a release candidate.
