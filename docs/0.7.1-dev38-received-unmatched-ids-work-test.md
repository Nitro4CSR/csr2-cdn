# Dev38 — Work-ready *received* unmatched numeric-ID diagnostic

## Purpose

This build finally identifies **the numeric IDs received from a current own-crew
roster response that are absent from the two source libraries for the same
attribute**. It does **not** report source numbering gaps as roster IDs and it
cannot reconstruct the intentionally discarded Dev24 roster snapshot.

The comparison is exact: numeric paint IDs are checked only against
`CarPaintLibrary` + `CarTunerStarsPaintLibrary`; interior IDs only against the
two interior libraries, and calliper IDs only against the two calliper libraries.
A number appearing in an interior library does **not** resolve a paint miss.
Zero is a valid numeric ID. An ID repeated on several vehicles is listed once
per attribute with an occurrence count and TNR-syntax versus other counts.

Presence is **source-ID membership only**, not proof that a car is eligible
for the cosmetic or that a label describes its appearance. Some IDs may exist
in the libraries but remain unresolved for a particular car due to
model-specific rules; those are counted as source-present rather than as absent.

## Option A — Work, reuse the previously validated Dev36 catalogue

1. Supply the Dev38 source ZIP plus `dev36-source-ids.json` and
   `dev36-summary.json` to a Work environment that supports Python, outbound
   game-service access and the package's existing authenticated CSR2 reader.
2. Make your own CSR2 PlayerID available privately as `CSR2_PLAYER_ID` in the
   process environment, **not as a command-line argument or a chat message**.
   Alternatively, use the command in an interactive terminal and enter the ID
   at the hidden prompt. Do not share portal tokens or session credentials.
3. Install the wheel or install the source with `python -m pip install .`.
4. Preview without network traffic:

   ```sh
   python -m csr2cdn.dev38_received_unmatched_ids \
     --catalog dev36-source-ids.json --summary dev36-summary.json
   ```

5. After explicit approval for the live crew read, execute:

   ```sh
   python -m csr2cdn.dev38_received_unmatched_ids \
     --catalog dev36-source-ids.json --summary dev36-summary.json \
     --execute --output dev38-received-unmatched-ids.json
   ```

This uses **zero public CDN requests** and **two game-service read operations**:
`crews/checkUserCrew` and `crews/viewMembers`. The existing service performs
portal authentication, and may re-authenticate or retry a read on 401, so two
read operations do *not* guarantee only two raw HTTP requests. They do not
modify game state.

## Option B — Work, retrieve the latest database for the selected release

```sh
python -m csr2cdn.dev38_received_unmatched_ids \
  --refresh-public --branch 6_8_0_Release \
  --execute --output dev38-received-unmatched-ids.json
```

This adds **at most eight public CDN GETs** for the branch's currently
advertised database and the six source libraries before the two game-service
read operations. The branch must be selected explicitly; "latest" here means
*latest database advertised by that branch*, not automatic discovery of the
newest game release branch.

## Offline-only replay if you already have previously saved own/member JSON

```sh
python -m csr2cdn.dev38_received_unmatched_ids \
  --catalog dev36-source-ids.json --summary dev36-summary.json \
  --own-json own.json --members-json members.json \
  --output dev38-replayed-unmatched-ids.json
```

This issues zero requests. Keep saved raw responses private; the tool never
copies them to its output.

## Outputs and privacy

The new private JSON file contains:

- `individual_absent_received_ids`: each real numeric ID (with `attribute`,
  `received_numeric_id`, `occurrences`, and TNR/other counts), ordered one by one.
- `coverage_by_attribute`: received, present, absent, and missing-field counts.
- `source_database_version` and six source hashes for reproducibility.
- `crew_member_rows`, snapshot completeness hints, and explicit non-promotion
  indicators.

Neither the output nor normal console text includes a PlayerID, player name,
crew identifier, model key, wheel string, raw server response, auth token or
cosmetic label. Output paths must be new; the file is created with restricted
permissions on POSIX. **Do not upload full raw own/member responses.** Share
only the redacted Dev38 JSON when you want help examining the unmatched IDs.

No archived Dev24 values are invented. Results from the current roster can
differ from the historical 10-paint/1-interior aggregate counts.

## Evidence level

The CLI's source-only comparison can establish a received ID is **absent from
all six source libraries in its own attribute** (paint, interior, calliper).
It cannot prove vehicle-eligibility, localization, wheel-name or visual joins.
This is a diagnostic build; existing decoders, labels and mappings are unchanged.
