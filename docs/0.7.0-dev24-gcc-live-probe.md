# Dev24: GCC current-progress leaderboard live probe (unreleased)

**Purpose:** Evaluate seasonal **crew** standings after the 2026-10-16 29-member contribution test. This is a deliberately opt-in, read-only experiment; do not publish results as verified season standings without comparing against the game UI. The game screenshots identified the Manthey 911 Prestige Cup as the active season. Reported historical UI reference: **37,448,821 RP, rank 257**. These values were snapshots, not current service confirmations.

## Implemented findings

- The previous dev23 authorized test found `cc_contrib` numeric for 29 distinct members. Several screenshots matched server values exactly, and the complete 37,463,129 RP member sum differed from the screenshot total by +14,308 (approximately 0.038%). `CrewMember.season_crew_rp` now promotes **only explicit, nonnegative, numeric `cc_contrib`**, never ambiguous fallback `score`, `player_rp`, or lifetime `rp`. The existing candidates are retained for audit. The server still does not emit a verified active-season ID to this model.
- Native `GrandCrewChampionshipManager.RequestLBDataProgress` RVA **0x38a7dac** obtains a `viewcrew` URL from `GetLeaderboardURL` **0x38aa8fc**, uses **SetupWithCommonRange** (`0x2bdc660`), then calls `PlayerCrewManager.FetchGrandCrewChampionshipProgress` (**0x34b83b8**) and the network builder at **0x3504770**.
- Native `GetLeaderboardURL` concatenates a **runtime-configured** endpoint prefix with the string `viewcrew`. The shipped binary's string-literal metadata contains **`leaderboard/crew-champs-v2/`** as a default prefix. Its runtime value and whether it selects the current 14-day season remain **unverified**.
- At RVA **0x3504770**, the request inserts `app_ver`, `top`, `after`, `before`, `offset` in that order, with native queued request category **3**. Common range is `top=10, after=5, before=5, offset=0`. The progress path is distinct from `RequestLBDataResults`, which uses a different range and may concern completed seasons.
- The full reconstructed **experimental** route is `leaderboard/crew-champs-v2/viewcrew`. This is an APK-default candidate, **not** a known authenticated success. The contract rejects any changed URL, range, request type or parameters.
- The response decoder reads only `RemoteCrewInfo.FromJSONDict` fields `uid`/crew name, `crew_rank`, `cc_rp` (seasonal total candidate) and `rp` (all-time). If the response has an unfamiliar wrapper it reports only allowlisted structural diagnostics, never raw response objects, account identifiers or authentication tokens.

## Run the focused, explicitly authorized live check

First install the wheel (or run directly from the source tree). In an interactive console:

```console
python -m csr2cdn.crew_rp_verification --execute --print-member-values --gcc-live --gcc-only --reference-total 37448821 --reference-rank 257 --season-note "Manthey 911 Prestige Cup"
```

This makes **at most one initial portal authentication exchange**, one `crews/checkUserCrew` read, and one **experimental** GCC progress read. It intentionally skips the roster read with `--gcc-only`. The read client may re-authenticate only if its built-in 401 mechanism is triggered. The only game operations are read-only; no game save/profile writes or publication.

The test prints crew names, ranks and RP candidates from the **actual response**, plus any match against the signed-in crew and the UI snapshot references. It does **not** print crew IDs, player IDs, secrets or raw network bodies. If the service rejects the experimental route, the test reports `validation_unavailable`, not an invented leaderboard. If the schema differs, it prints a bounded known-key census for follow-up.

For a joint roster + GCC comparison, omit `--gcc-only`, supply `--expected-members 29`, and keep `--print-member-values`; this prints member nicknames, RP values and GCC crew rows. Avoid distributing raw local value transcripts without member approval.

For a fully offline mode, use `--gcc-response-json` with already captured genuine JSON; no authentication/network calls occur.

## Still blocked

The progress URL is inferred from the APK-default prefix and native concatenation, not a runtime-configured URL confirmed on the active account. Results, `cc_rp` coverage, rank semantics and actual active 14-day season are untested. Member field coverage is established but rollover is untested. The independently reported Prestige 21-row success remains preserved and was not rerun. Role accuracy, other release gates and CI remain outstanding. **Do not release or publish 0.7.0.**
