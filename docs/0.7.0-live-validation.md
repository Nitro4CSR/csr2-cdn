# CSR2 0.7.0 live-read validation

This is an **experimental, authorized-account, read-only test**. It never
downloads/updates save games, participates in races, posts results, or retrieves
chat. No request bodies, credentials, raw responses or account records should
be attached to bug reports. Run from an interactive shell on your own computer.

## Install from the development wheel

```console
python -m pip install 'csr2_cdn-0.7.0.dev9-py3-none-any.whl[events]' 
python -m csr2cdn.live_validation
```

Install `UnityPy>=1.20` with the wheel's `events` extra; the first command above installs local code; the second confirms dry-run mode
(`network_requests: 0`). The harness will not contact any service until
`--execute` is explicitly supplied.

## Staged live checks

1. `python -m csr2cdn.live_validation --execute`: choose your own PlayerID
   at the hidden interactive prompt. First query the current metadata and
   inspect Showdown candidate counts. This build automatically fetches current
   type-47 ASTC-quality event bundles from the asset database and attempts to
   decode them with UnityPy before picking a board. If exactly one active event
   has a full resolved server board name, one standings read is attempted.
2. `--showdown-name "Championship Showdown"` selects a current metadata
   `SMP_SHOWDOWN_<season>_W2`; "Elite Showdown" selects an active `_W1`.
   If the slot is not running, `inactive_event` is reported. A season number is
   never calculated from local time or hardcoded. Exact metadata names still work.
   This resolves an event by its user-facing name.
   If discovery reports `runtime_catalogue_unavailable`, an asset could not
   be downloaded or decoded, so the absence of current events is *unknown*.
   If discovery reports `unresolved_board`, it may mean no supported current
   event, multiple concurrent events, or incomplete identifier resolution.
   Do not substitute a schedule event ID for the board name.
3. If you already know an **authoritative** resolved board name, provide
   `--showdown-board RESOLVED_BOARD` to test it explicitly. If the
   metadata supplies multiple fully resolved active boards, choose one
   with `--showdown-index 0` (or `1`, etc.); the index is zero-based
   and sorted by event ID. The developer
   should verify that it is a Showdown board before interpreting scores.
4. Crew membership discovery now runs by default using your own PlayerID,
   followed by the roster lookup if membership is confirmed. **No crew UID
   is required.** Add `--skip-crew` to disable that check, or optionally
   `--crew-uid OWN_CREW_UID` for a known crew. An optional
   `--prestige-board RESOLVED_BOARD` is tested only if the board is known;
   never guess a leaderboard name.
5. `--leagues-board` is for optional legacy compatibility only: Showdown
   Leagues is discontinued in the current game.

The metadata service uses a product version that may differ from the APK's
`6.8.0` version. This harness asks the CDN client to resolve it; you may
explicitly supply `--metadata-product-version` if already known. Use
`--skip-metadata` to isolate a directly supplied board/crew read.

Crew lookup requires two different read operations (membership and members).
Every selected operation uses a bounded network response and one logical read,
except bounded authorization retries required during session establishment
or when an authorization response is rejected. The test
report intentionally contains **only** time, non-sensitive version, per-check
status and record counts; when an unrecognized crew JSON object is returned,
it can also include a bounded **field-count-only** response structure summary,
never field names, values, tokens or player records. It never writes files.

## Interpreting status

| Status | Meaning |
|---|---|
| `ok` | A request completed and its response matched the current decoder |
| `unresolved_board` | No unique, fully resolved Showdown board was available |
| `inactive_event` | No currently scheduled event exists for the requested Championship/Elite slot |
| `runtime_catalogue_unavailable` | Runtime event bundles could not be fully decoded; absence of events is not established |
| `not_selected` | Optional check was deliberately skipped |
| `not_in_crew` | Own-crew lookup did not return an active crew |
| `transport_unavailable` | A directly observed connectivity/timeout failure |
| `http_rejected` | The request received a non-success HTTP status |
| `response_not_recognized` | Response JSON didn't match the provisional typed model |
| `service_unavailable` | Request could not complete or response couldn't be accepted |
| `unexpected_failure` | Unexpected test failure; no internal details logged |
| `interactive_terminal_required` | Secure input isn't available in this shell |

An `ok` result verifies the tested read only. It does not prove every account,
segment, event, expired board, or pagination mode is supported. All other
features retain their provisional designation until individually exercised.

## Environment limitations

An authorized dev8 check confirmed runtime bundle loading, session setup,
own-crew membership, and one active Showdown standings read (21 entries).
Crew roster structure, leaderboard rank/score interpretation, and Prestige Cup
still require live checks. Run locally
on a machine with authorized access. Provide only the sanitized JSON report
for interpreting failures and improving the client.
