# CSR2-CDN 0.7.0.dev10 — Prestige Cup discovery

## Why `0.7.0.dev8+prestige1` did not find the active event

The October 15 live report shows the runtime metadata decoder worked, but the
Prestige selector accepted **zero** of 82 groups. Its only input was the
Showdown event catalogue. That does not establish that Prestige Cup is absent.

## Client evidence (CSR2 6.8.0, ARM64 `libil2cpp.so`)

- `RaceEventData.IsPrestigeEvent` at RVA `0x32d8d40` obtains
  `RaceEventGroup.get_TelemGroupName` (`0x32fb140`) and compares that result
  to a client constant. The categorization therefore must not depend solely on
  the display or metadata group name. The exact constant has not been
  independently established from the production payload.
- `RaceEventDatabase.LoadCupInvitationalRaceSeries` at RVA `0x32f47a0`
  loads a `CupInvitationalSeriesDatabase`. `RaceEventDatabase.SetAndProcessCupInvitationalEvents`
  at RVA `0x32f4920` processes `SeriesEventCollection.ProcessEvents` at
  `0x331c260`. `SeriesEventCollection` contains `RaceSeries`; `SeriesEvent`
  includes `EventFile`, timing, and series identity. A `SeriesEvent` alone does
  **not** provide an attached leaderboard or a first race ID.
- `EventLeaderboard.RefreshGlobalStandings` ultimately uses the generic
  authenticated progress read. The global range includes `show_default=true`;
  the four-input event-board identifier is only constructed where complete
  schedule, rank definition, first race and leaderboard attachment exist.

## Dev10 changes

- Keeps the live-verified dev9 crew decoder and Championship/Elite Showdown
  selectors (unlike the earlier dev8-based Prestige preflight branch).
- Fetches the separate `CupInvitationalRaceSeries` metadata block using the
  caller's PlayerID and metadata product version; retrieves type-47 modular
  event bundles through the already-existing asset CDN decoder.
- Preserves `RaceSeries` from modular event assets separately instead of
  inserting nested cup-series groups into the Showdown catalogue.
- Searches both cup-series nested groups and standalone/modular event groups.
  Prefers `TelemGroupName` when classifying Prestige. The old string
  `EventFile` lookup is invalid: both native `SeriesEvent.EventFile` and
  `RaceEventGroup.EventFile` are int32, and matching numeric values do not
  prove Prestige classification or a leaderboard attachment.
- Reuses the game schedule/ranking/first-race derivation after a group is
  identified, and emits no board request when these inputs are incomplete.
- Prepares generic event-leaderboard `/view` requests with
  `show_default=true` and a time-derived `offset`.
- Exposes `CSR2Services(player_id, allow_network=True).get_prestige_cup_leaderboard()`
  for the PlayerID-only workflow, and `python -m csr2cdn.live_validation
  --execute --skip-crew --prestige-current` for a read-only smoke test.

## Important remaining validation

The supplied live report contains counts but no raw, redacted cup-series
structure. The dev10 discovery logic is **offline-tested against synthetic
CupInvitationalRaceSeries and common-event fixtures**, not yet proven to
resolve the active production Prestige Cup. An event series may contain only
`EventFile` references rather than embedded groups; in that case more native
reference-resolution work is needed. `cup_series_entries` and
`cup_nested_groups` in the sanitized report distinguish this situation.

Do not count `prestige_discovery: unresolved_input` as a successful release
check. If discovery succeeds, verify the server response, player ranks, score
units, and pagination independently before final 0.7.0 publication. Never
persist account material or raw player records in a report.
