# Dev18: Crew roster RP wire case and crew-role validation

This is a **read-only development build**, not an assertion that roster RP
matches the in-game *current-season* Crew RP. No authenticated member data,
PlayerIDs, credentials, APK binaries, or full responses are included here.

## Independent live finding from dev17

The user's independent Windows/Python 3.13 run (2026-10-15 23:53:55 UTC)
returned 29 crew members, with nickname and player level for 29/29 and typed
`crew_rp` for 0/29. Zero values would have been counted, so this is missing
extraction rather than zero Crew RP.

## CSR2 6.8.0 native evidence

The ARM64 `PlayerCrewMember.FromJSONDict` method (RVA `0x34a3d78`) loads
string-literal `RP` (**uppercase**, metadata literal index 16594) at
`0x34a4a78`, checks the corresponding dictionary field and passes a pointer
at `object + 0x90` to its numeric conversion call at `0x34a4a9c`.
The dev17 Python decoder looked for only `crewRP`, `crew_rp`, `crewRp`,
and lowercase `rp`. This exact casing gap has been fixed.

The native `PlayerCrewMember` contains *distinct* `RP_allTime` and
`RP_season` fields. The object has the roster `RP` value at offset `+0x90`.
The game's `CrewRankPanel.RefreshUI` reads `+0x94` (seasonal RP) at
`0x269ab08`. `PlayerCrew.set_Members` (RVA `0x34a5518`) updates `+0x94`
for the local player using profile state at `0x34a5754`. **Therefore,
`RP` must not be declared proven equal to seasonal Crew RP just because
its wire casing is now decoded.** Another source or calculation may be
required for the seasonal value of other players.

The separate native `CrewRole` enum has `NEWBIE`, `MEMBER`, `SENIOR`,
`ADMIN`, `LEADER` values 0–4, confirmed by
`PlayerCrewNetwork.GetCrewRoleFromString` (RVA `0x34ff9ec`). The Python
`role` field remains the original wire representation; `role_normalized`
provides one of those canonical names for known string or integer inputs.

## Added public attributes

| Property | Behavior |
| --- | --- |
| `member.crew_rp` | Prefer explicitly named season/crew aliases, then native uppercase `RP` and compact-list `rp`; `None` if absent/invalid |
| `member.crew_rp_source` | Exact known *field name* that populated `crew_rp`; no private values |
| `member.rp_all_time` | Native uppercase `RP` value, separately exposed because seasonal equivalence is unverified |
| `member.role` | Original stringified role, preserved for backward compatibility |
| `member.role_normalized` | One of `NEWBIE`, `MEMBER`, `SENIOR`, `ADMIN`, `LEADER`, or `None` if unknown |

Values of zero count as populated. Unknown/invalid fields are never turned
into invented numbers or role names. The lower-case `rp` field remains
supported for the two native compact member-list overloads.

prove season RP; privately compare individual displayed values against

separate seasonal member-score source rather than re-label the uppercase
