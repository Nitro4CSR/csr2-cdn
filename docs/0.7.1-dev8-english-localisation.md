# 0.7.1.dev8 — Observed UnityFS English car-name source

The operator supplied `Localisation_EN.ASTC.6312`, a genuine UnityFS v8 CDN asset (Unity 2022.3.62f2). SHA-256: `cfaeb6144f487d2fd4b3926d1c1bbe94d8c0391e51216004d6c0ede09dbc425c`, size 836,973 bytes. Its 21 LZ4-compressed data blocks contain a 2,686,604-byte Unity serialized node and `TranslationDataAsset_Localisation_EN` object with language `EN` and project `CSR2`.

The observed translation object contains two parallel arrays: **26,854 distinct keys** and **26,854 English values**, indexed in order. Exactly 1,341 keys of each kind `TEXT_CAR_<DBName>_{SHORT,MEDIUM,LONG}` were found. Because four model identifiers have incomplete variant coverage, this represents **1,343 distinct raw model identifiers** and **1,339 complete sets**. Missing style variants are not fabricated.

Four incomplete keys in this version: `Koenigsegg_AgeraRSTOCK_2013` (SHORT and LONG only); `BMW_LBM4CoupePlayer_2014` (MEDIUM only); `Ferrari_812CompetizioneRewardRecycled_2021_2021` (LONG only); and the unusual model identifier `NOT LOCALISED` (SHORT and MEDIUM only). `NOT LOCALISED` should be treated as a source record, not a confirmed car DBName.

For example `Porsche_Manthey911GT3RSRewardRecycled_2024` resolves to SHORT and MEDIUM = `Manthey 911 GT3 RS (992.1)`, LONG = `Porsche Manthey 911 GT3 RS (992.1)`.

Unlike dev7's **layout-specified FlatBuffers** decoder, this source is **a UnityFS bundle containing a Unity serialized asset**, and the observed object layout is directly supported. `csr2cdn.localisation_bundle.load_localisation_unityfs()` decodes a bounded local file with optional `lz4` (`pip install 'csr2-cdn[events]'`). A client may use the returned `GameCarTranslations` model with the existing `CarNameStyle` enum (`MEDIUM` default).

Two CLI integration paths, **both offline and read-only**:

```bash
python -m csr2cdn.native_source_validation --translation-unityfs ./Localisation_EN.ASTC.6312
python -m csr2cdn.native_source_validation --translation-unityfs ./Localisation_EN.ASTC.6312 --output-translations-json ./car_names_en.json
python -m csr2cdn.crew_bulk_validation --translation-unityfs ./Localisation_EN.ASTC.6312 --car-name-style MEDIUM
```

The bulk probe dry run still performs zero requests; source-specific name matching is used in offline/live bulk reports once roster response data are supplied. Individual member details require explicit `--show-members`.

### Boundaries

- Only the **observed English asset structure** is supported. Different Unity serialization formats or non-English assets need independent verification.
- A few official translation values have stray surrounding spaces or line breaks. These are **trimmed for display**; interior spaces, Unicode and capitalization are preserved. The underlying asset is not modified.
- This decoder establishes **car display names**, not any paint, wheel, decal, livery or visual-code library mappings. Those remain distinct work.
- The source asset and full translations are never shipped inside the wheel/source distributions. Users supply them locally. No authenticated game reads or fresh CDN downloads were performed in dev8.
