# Named Showdown resolution — 0.7.0.dev5

**Status:** Native identity format recovered from CSR2 Android 6.8.0; offline
workflow tested. The real October 2026 Showdown leaderboard remains unverified
until an authorized read succeeds and the results are compared with the game.

## Intended public interface

A user only supplies their own PlayerID and the Showdown name. Metadata product
version, current Showdown event/group, schedule, first race ID, ranking order,
board-name construction and read parameters are handled internally.

```python
from csr2cdn import CSR2Services
with CSR2Services("YOUR_PLAYER_ID", allow_network=True) as api:
    page = api.get_showdown_leaderboard(showdown_name="Championship Showdown")
```

```sh
csr2cdn services --execute showdown --name "Championship Showdown"
# PlayerID input is hidden in an interactive terminal
```

For **offline** debugging with real or synthetic metadata (not live):

```sh
csr2cdn services --metadata-dir ./ConfigData \
  showdown --name "Championship Showdown"
```

The command defaults to request preview without `--execute`. The provided
Showdown name is matched case-insensitively and ignoring punctuation and spaces,
not by loose substrings. Multiple simultaneous Showdowns are not conflated.

## Native evidence (CSR2 6.8.0)

- `RaceEventGroup.get_LeaderboardGroupIdentifier` RVA `0x32fb0dc` calls
  `RaceEventData.get_EventID` RVA `0x32cfe10` on the first race in the group.
- `EventLeaderboard.get_LeaderboardUniqueID` RVA `0x3388010` has a
  different profile-dependent branch when the leaderboard type is `1`.
  Its production applicability still needs checking. The normal branch uses
  `evnt-off-{0}-dur-{1}-hours-{2}---{3}`.
- The four arguments are event-start offset hours within its duration relative
  to `2018-01-01T00:00:00Z`, whole duration hours, the ranking-order string
  (`asc` for `rankingOrder == 0`, `dsc` otherwise), and the first race's
  integer EventID.
- The native client obtains its start and duration via `GetTimeData`, which
  calls `RaceEventGroup.GetTimeStart/GetTimeEnd`; these can depend on event
  schedule and repeat cycles. The package does **not** treat a Showdown name,
  schedule ID or `LeaderboardTemplateID` as a board name.

## Metadata resolution

`ShowdownEventsContainer.RaceEventGroups` supplies the group label, `ScheduleID`,
`RaceEvents`, and its nested `Leaderboard.LeaderboardTemplateID`.
`EventSchedule.ScheduleList` supplies timing, including some inherited schedules
through `BasedOn_ScheduleID`. `EventLeaderboards` supplies the ranking definition
indexed by template `nameID`. When a supplied complete, dated interval is
recognizable, the normal-mode server leaderboard name is reconstructed.

The scanner recognizes timezone-aware ISO-8601 or Unix-second/millisecond
start/end pairs, and arrays of complete pairs under `Time_ActiveBetweenAny`.
It follows inherited `BasedOn_ScheduleID` only for *missing* time criteria.
Unknown date representations, invalid/cyclic schedule references, overlapping
currently active windows, unsupported events under an hour, absent first race
ID, absent rankingOrder, and ambiguous names are **unresolved** rather than
being silently guessed. Time-window activity is not proof of server eligibility.

The local validation report showed `Time_ActiveBetweenAny` and
`BasedOn_ScheduleID`, but did **not** include their raw value shapes or a live
board response. Therefore the new resolver is a stronger first implementation,
**not** proof that every real Showdown schedule can be decoded. In particular,
repeat-event rotation and segmentation must be compared with a real metadata
snapshot before treating a named event read as live-verified.

## Security and scope

No save downloading/uploading or game chat retrieval. No player ID, auth token,
nonce, signed request, session step, raw response or request body is written to
package diagnostic logs. Network requests remain explicit opt-in and read-only.
The legacy Showdown Leagues interfaces remain available separately.

## Reproducible offline demonstration

A **synthetic** (not live) fixture exercises all four ID inputs and inherited
schedule selection:

```sh
csr2cdn services \
  --metadata-dir tests/fixtures/showdown_native_synthetic \
  --at 2026-10-15T12:00:00+00:00 \
  showdown --name "Championship Showdown"
```

This prints a `leaderboard/evnt-off-.../view` request preview. No network
connection, PlayerID or live authentication is needed for the demo.

An authorized smoke test can be run later with:

```sh
python -m csr2cdn.live_validation --execute --showdown-name "Championship Showdown"
```

It reports only status codes, counts and missing-*category* counts under
`unresolved_input_categories` (for example, `schedule_window`). It never prints
the PlayerID, event records, authentication material, or signed request.
