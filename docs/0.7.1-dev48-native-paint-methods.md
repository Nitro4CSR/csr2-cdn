# Dev48 — verified native paint method pointers and crew snapshot copy

## Source evidence (CSR2 6.8.0 APK, offline)

Dev48 resolves managed method tokens from IL2CPP v31 `global-metadata.dat` into **native ARM64 RVAs** by locating the actual `Assembly-CSharp.dll` code-generation module inside `libil2cpp.so` using relocation references. Unlike Dev46/Dev47, this verifies the compiled body bytes, not just the managed name/signature. The report contains **no APK, disassembly, private crew data or source binaries**. All method bodies are fingerprinted with SHA-256; byte spans are measured to their neighboring method pointer only when safely bounded (not guaranteed function-size boundaries).

Real APK: module method pointer count **93,371**. Verified examples:

| Type.method | Native RVA | What native disassembly establishes |
|---|---|---|
| `CarPaintLibrary.GetIDByIndex` | `0x319e03c` | Checks negative index/bounds; accesses index in paint-record list, returns an ID; returns 0 for negative/out-of-range index |
| `CarPaintLibrary.GetIndexByID` | `0x319e0c4` | Traverses paint-record list comparing ID; returns an index or -1 on missing ID |
| `CarTNRPaintLibrary.GetIDByIndex` | `0x31a81c0` | Separate TNR list; same negative/out-of-range-to-zero behavior |
| `CarTNRPaintLibrary.GetIndexByID` | `0x31a8248` | Separate TNR list; returns an index or -1 when no matching ID |
| `CrewMemberCarInfo.SetPaint` | `0x35793b4` | Direct `STR W1,[X0,#0x20]`, then `RET`; stores supplied index without an ID conversion in this method |
| `SMPHostInfo.UpdatePaintIndex` | `0x3437c84` | Direct `STR W1,[X0,#0x68]`, then `RET` |
| `CarVisuals.SetPaintIDAddIfNecessary` | `0x3813de4` | Searches the car's paint-ID list and appends requested ID when absent; this is a different path from storing the selected index |
| `CrewMemberCarInfo.GetCurrentPlayersCurrentCarCrewMemberCarInfo` | `0x357941c` | In one branch copies `LDR W8,[X0,#0x6c]` into `STR W8,[X22,#0x20]` of the crew-car snapshot, consistent with taking the applied paint index from a selected garage car. No lookup occurs between these two instructions |
| `FtueDealershipCarsConfig.GetForceDefaultPaint` | `0x32c2d44` | Returns a boolean config value or false for null backing data; does not return a numeric paint ID |
| `ConfiguratorMenuScreen.ShouldShowDefaultPaintForCar` | `0x2828158` | Calls the dealership force-default config path as a prerequisite and then another car-specific decision; not a definition of paint ID 0 or 15 |

### Critical limits

- The store and crew-snapshot copy paths **strengthen the native index hypothesis for the crew model**. The server's JSON `car_paint_id` wire serialization/deserialization has **not yet been traced to this native copy**.
- A received value of `15` might be an index, but no car-specific paint-list position was resolved or trusted.
- `GetIDByIndex` returning 0 for an invalid index **does not mean** that all roster zeros are error values, or that the name `Transparent` is the game's paint default. `Transparent` remains an operator-approved display alias.
- Valid paint IDs in the million-range also appear in the roster. Do not install a universal `index -> ID` conversion or prune currently mapped IDs without proving where and when translation occurs.
- Adjacent method-pointer RVAs are an evidence extraction bound, not an authoritative decompiler function-size oracle. Some non-monotonic pointers are intentionally reported without a byte span.

## Offline reproduction

```bash
python -m csr2cdn.dev48_native_paint_methods \
  --apk CSR2_6.8.0.apk \
  --output dev48-native-paint-methods.json
```

The analyzer does not connect to the internet, access player accounts or ingest roster data. It refuses to overwrite its output. The APK and native `.so` are **excluded from distributions**. On a system with LLVM ARM64 disassembly support, use the reported RVAs with `llvm-objdump` against your own extracted `libil2cpp.so` to inspect method bodies and surrounding call sites. Do not infer a wire mapping from method names alone.
