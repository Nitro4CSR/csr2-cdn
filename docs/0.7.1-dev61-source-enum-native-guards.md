# Dev61 — eCarSource enum defaults and pre-unlockable source guards

**Source basis:** operator-provided CSR2 6.8.0 APK, cached crew response (private, not included), Ford_Mustang302_1970_common.ASTC.14 (operator bundle), database 34011 public source catalogue. All analysis runs offline. No newly authenticated responses, game requests or network calls.

## Findings

Dev60 left two conditional values, paint ID 129 (*Ford Magnetic*) or 1323 (*Ford Dark Highland Green*) at received index 15, depending on an earlier appending of a garage-visual paint before the aftermarket unlockables are expanded.

Dev61 decodes `eCarSource` **constant defaults** from IL2CPP metadata version 31 (one-byte compressed signed values, rather than treating the compressed data as 32-bit integers). The exact enum fields are:

| Name | Value |
|---|---:|
| Unknown | 0 |
| Tutorial | 1 |
| Gacha | 2 |
| ShopCash | 3 |
| ShopGold | 4 |
| High_Stakes | 5 |
| GenericRewards | 6 |
| IAP | 7 |
| IAPSpecial | 8 |
| Prize | 9 |
| Collection | 10 |
| Temp | 11 |

`CarVisuals.Setup` loads this car-source integer from garage offset `+0x108` at native RVA `0x38029a4`, testing `((1 << source) & 0x604) != 0` for Gacha (2), Prize (9), and Collection (10). When the mask is not satisfied, it calls `eCarSourceExtension.IsIAP` at `0x3475484` via the verified callsite `0x3802b94`. The full helper body returns true precisely for enum values 7 and 8. A false return branches past the source-specific early paint append site to `0x3802d0c`.

The *single matching* cached crew vehicle with paint index 15 has `car_source = Tutorial`, no gacha payload, aftermarket milestone level 50 and restoration-status number 0. The analyzer reveals **no private player identity**. `Tutorial` maps to enum 1 and matches neither guard. **Therefore the earlier paint append responsible for the Dev60 `129` alternative is ruled out under the observed crew-source interpretation**. The unchanged native base+deduplicated unlockables replay at index 15 gives paint ID 1323 (*Ford Dark Highland Green*).

## Limitations

This result is a **conditional static reconstruction**, not a captured rendering frame or proven production paint join. In particular:

- The roster's source text must be mapped into the same native enum on the crew rendering/garage instance.
- The runtime visual list must start with the decoded base list and include the uploaded serialized `AllUnlockables` ordering, without unobserved mutations.
- Milestone level 50 and restoration status 0 are observed values, **not** proof of a specific runtime-state transformation.
- The garage car's original paint-ID value has not been recovered, but this specific source guard now makes its relevance to the *early source-specific append* less likely for Tutorial.
- Other code paths could still reorder or extend the list. Paint `0` remains unresolved for other vehicles.

No production mapping changed. The Dev60 alternative's elimination is scoped to the **two examined `CarVisuals.Setup` source guards**, not a categorical guarantee that no runtime paint insertion happens anywhere.

## Offline reproduction

```bash
python -m csr2cdn.dev61_source_enum_guard \
  --apk CSR2_6.8.0.apk \
  --bundle Ford_Mustang302_1970_common.ASTC.14 \
  --source-catalog dev36-source-ids.json \
  --private-cache-zip endpoint-cache.zip \
  --car Ford_Mustang302_1970 --paint-index 15 \
  --output dev61-guard-report.json
```

The private cache flag is optional; without it, the tool still pins the native branches but cannot claim they are excluded for a specific roster record. The report never contains account/person identifiers or raw crew JSON. Source and wheel exclude game assets and private cache.
