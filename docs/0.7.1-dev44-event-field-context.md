# Dev44 — Context-aware cosmetic source evidence (offline)

Dev44 examines only six event-metadata JSON documents in an existing local endpoint cache, separately from the public Dev36 cosmetic-ID catalogue. It makes **zero** server/gameplay requests and does not read the cached `game/` folder. Input sources must be pre-existing and integrity-checked against manifest SHA-256 and byte size.

## Run from a Work session or locally

```bash
python -m csr2cdn.dev44_event_cosmetic_context \
  --cache-zip endpoint-cache.zip \
  --source-catalog dev36-source-ids.json \
  --baseline-evidence dev44-offline-metadata-evidence.json \
  --output dev44-event-context-audit.json
```

Alternatively, use `--cache-dir endpoint-cache` instead of `--cache-zip`. The exact ZIP from the existing capture is preferred; no extraction of the game cache is necessary. `--output` refuses an existing path. The report is aggregate and must not include event names, raw strings, player identifiers, crew responses, or a saved roster.

## Field relationships and limitations

| Context | Field(s) | Evidence | What is NOT established |
|---|---|---|---|
| Event record, AI appearance | `AIPaintID`, `AIInteriorID`, `AICalliperID` | Exact integer membership in matching paint/interior/caliper standard/TNR libraries | Whether every source row is compatible with a car; whether roster wire fields use the same complete set of semantics |
| Event record, AI wheel | `AIWheelType` | Strings (including blank/null) and counts-only grammar | Whether a string joins to any TNR rim/source wheel asset |
| Race restrictions | `Restrictions[].CarPaintID` | Separate restriction-field counts | That `0` names the actual chosen paint color of AI or roster cars |
| Player roster | `car_paint_id`, etc. | Not read here | No new roster-field join or label acceptance |

`2147483647` (`0x7FFFFFFF`) occurs repeatedly as an absent event AI cosmetic source-ID value; this is a **sentinel candidate**, NOT decoded native semantics. A different absent numeric value is reported only as an aggregate under `other_unlisted`. Cross-version equivalence is not claimed: the metadata capture has no independently verified database version, whereas the public Dev36 catalogue records database 34011.

The user-approved display alias `paint ID 0 → Transparent` remains separate from native field/source semantics. Player-roster paint ID 15 remains unresolved.

## Verified existing-cache measurements

Against the uploaded endpoint-cache archive and Dev36 source catalogue:

- 1,042 event records contained AI cosmetic fields (including seven CareerRaceEvents tutorial/WinACarEvent records outside the `RaceEvents[]` arrays).
- Paint: 813 source matches, 229 absent; interior: 816 matches, 226 absent; calipers: 816 matches, 226 absent. All source-absent AI values were `2147483647`.
- 76 occurrences of `Restrictions[].CarPaintID = 0` in IconsCampaign. No causal/semantic mapping to roster paint zero.
- The new report's per-block match/absence counts reproduce `dev44-offline-metadata-evidence.json` exactly when supplied as `--baseline-evidence`.
- Wheel syntax profiles are counts-only; wheel strings are not exported and no roster wheel resolution is performed.

## Security and reproducibility

The source reader allowlists precisely six public `metadata/*.meta` paths and never opens game/crew/leaderboard response bodies. ZIP inputs are checked for duplicate members, selected entry size and symlink type; existing-cache manifests must include SHA-256 and size for each selected file. The standalone input catalogue is bounded; output is exclusive-create. Never package or publish `endpoint-cache.zip`, cached metadata, game responses, private cache manifests, or private key-path files. Test fixtures are synthetic; the full regression suite is separate from the real local replay.
