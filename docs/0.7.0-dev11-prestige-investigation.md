# Prestige Cup source correction — CSR2 6.8.0

## What the dev10 live report established

The actual cup metadata block loaded, containing 1,578 series entries; no
Prestige-classified groups were recognized and no leaderboard request was
sent. Local observed `EventFile` values are integers (not string file paths),
`EventGroupName` values are null, and series labels belong to CREW/PRIZE/
SUPPLY/TOKEN categories. The absence of Prestige in that block does not prove
there is no active Prestige Cup.

## Reproducible native code findings

- `SeriesEvent.EventFile` and `RaceEventGroup_JsonData.EventFile` are int32.
  `RaceEventGroup.get_EventFile` (RVA `0x32fb2a8`) directly returns the int32
  at its serialized object offset `0x158`. It does not construct an asset path.
- `SeriesEventCollection.ProcessEvents` (`0x331c260`) iterates `RaceSeries`
  and invokes `RaceEventTopLevelCategory.ProcessEvents` (`0x3313aac`) on each
  `SeriesEvent`. That method traverses the inherited `RaceEventGroups`.
- `RaceEventDatabaseData.ProcessEvents` (`0x32f3374`) separately processes
  `SMPRaceEvents` and `SpeedTrapEvents` from `CareerRaceEvents`.
- `RaceEventDatabase.LoadInvitationalEventsConfig` (`0x32f4554`) loads
  `InvitationalRaceSeries` separately from cup-invitational series.
- `RaceEventData.IsPrestigeEvent` (`0x32d8d40`) reads its parent
  `RaceEventGroup.get_TelemGroupName` (`0x32fb140`). No client evidence
  supports treating generic CREW/TOKEN series as Prestige Cup.

## What changed in this diagnostic candidate

The package now loads CareerRaceEvents and InvitationalRaceSeries in addition
to existing cup and runtime bundle sources. It extracts race groups without
inventing group names, event IDs, or leaderboard names. Exact numeric EventFile
value matching is **not** used as a Prestige classifier. Positive client-derived
Prestige classification and a valid attached leaderboard are still mandatory.

The sanitized validation summary exposes `career_race_groups`,
`numeric_eventfile_records`, `positively_classified_prestige_groups`,
`additional_sources_loaded`, and `additional_sources_unavailable`.

## What is still missing

Without actual permitted local metadata contents or a successful authorized
live request, this does not establish which source contains the **active**
Prestige event or whether that event has an EventLeaderboard. This candidate
must not be released as final 0.7.0. A further local test should compare
source coverage and candidate counts, then request an authoritative resolved
board only if one is found. Logs must not contain credentials, PlayerIDs,
request signatures, or private scores.
