# Dev40: evidence-based paint ID 0 / 15 investigation

Dev40 uses sanitized *existing* evidence reports, not raw player or roster data:

- `dev36-source-ids.json` and `dev36-summary.json`: standard and TNR cosmetic source IDs, branch `6_8_0_Release`, database `34011`.
- `dev38-received-unmatched-ids.json`: fresh current roster reported eight paint ID `0` and one paint ID `15` occurrences missing from both paint libraries.
- `dev39-color-overlap.json`: same database; color palette ID `0` is named **Transparent**, color palette ID `15` is absent.

The operator explicitly accepts **Transparent** as the display label for paint ID `0`. Dev40 supports this as **operator-approved display evidence** with `--accept-transparent-zero`—not as an automatic/native source-ID paint mapping. The label is not applied to the production `GameVisualLibrary`/`CrewMemberVehicle` resolver. There remains no proven paint-ID-to-color-ID namespace relationship, and the optional CLI output records both the approved label and that limitation.

## Offline-only evidence review (zero requests)

```sh
python -m csr2cdn.dev40_paint_id_investigation \
  --received-report dev38-received-unmatched-ids.json \
  --palette-report dev39-color-overlap.json \
  --catalog dev36-source-ids.json \
  --summary dev36-summary.json \
  --accept-transparent-zero \
  --output dev40-paint-id-evidence.json
```

The report shows each **actually received** unresolved paint ID individually, with source palette evidence, other-attribute numeric overlaps (explicitly NOT paint matches), approved display label if opted in, occurrence counts and prior database provenance. It rejects report/schema/hashes/versions/counts that contradict each other. Output files must be new and are created with POSIX owner-only permissions where supported. No roster, player identifiers, model keys, credentials, original bundles, or game access are required.

## Opt-in narrow public CDN wrap check (three GETs, no game reads)

```sh
python -m csr2cdn.dev40_paint_id_investigation \
  --received-report dev38-received-unmatched-ids.json \
  --palette-report dev39-color-overlap.json \
  --catalog dev36-source-ids.json \
  --summary dev36-summary.json \
  --accept-transparent-zero \
  --online-wrap \
  --output dev40-online-wrap-evidence.json
```

The command uses the selected branch already recorded in Dev38 to GET the advertised version, asset database index, and **only the current `CarWrapLibrary.ASTC`**. The asset path, version, size, decode schema and SHA-256 are checked. No player/account authentication or gameplay requests. It does *not* re-download the six cosmetic libraries or reread the roster. The wrap library is a **separate namespace** and matching `15` there would NOT resolve paint ID `15`.

If a previously saved original wrap source is available, use `--wrap-bundle PATH` in place of `--online-wrap` (zero requests). The local mode does not claim to know which database the standalone local bundle came from.
