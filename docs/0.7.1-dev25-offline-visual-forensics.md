## New CLI: strictly offline

```sh
python -m csr2cdn.dev25_visual_forensics
```

No `--execute` or authenticated mode exists. It produces `network_requests: 0`
and an input checklist without reading private data. To audit the primary
source fields only, give the operator-supplied ASTC bundles (one or all three):

```sh
python -m csr2cdn.dev25_visual_forensics \
  --visual-asset-bundle CarTunerStarsPaintLibrary.ASTC.412 \
  --visual-asset-bundle CarTunerStarsInteriorLibrary.ASTC.393 \
  --visual-asset-bundle CarTunerStarsCalliperLibrary.ASTC.382 \
  --output dev25-source-audit.json
```

This audits the original UnityFS bytes with the unchanged primary decoder,
then independently counts `IncludeToCar` integer values, global `All` vs
model-specific `Category` records and uninterpreted bytes after the primary
array. **Neither the meaning of `IncludeToCar` nor the supplementary
eligibility/exclusion tables is established.** Audit output does not include
actual model keys or cosmetic names. `trusted_car_specific_eligibility` stays
false even if the primary array can be parsed.

To recheck the paint/interior gaps, provide an *already locally saved*,
authorized pair of own-crew / member-roster JSON fixtures, a matching local
asset database, and **all six original comparison libraries**:

```sh
python -m csr2cdn.dev25_visual_forensics \
  --asset-database asset_database_6_8_0_Release \
  --own-json local-private-own.json \
  --members-json local-private-members.json \
  --visual-asset-bundle CarPaintLibrary.ASTC.1195 \
  --visual-asset-bundle CarInteriorLibrary.ASTC.1139 \
  --visual-asset-bundle CarCalliperLibrary.ASTC.1004 \
  --visual-asset-bundle CarTunerStarsPaintLibrary.ASTC.412 \
  --visual-asset-bundle CarTunerStarsInteriorLibrary.ASTC.393 \
  --visual-asset-bundle CarTunerStarsCalliperLibrary.ASTC.382 \
  --output dev25-private-safe-aggregates.json
```

Add existing `CarColorLibrary` and `CarTunerStarsRimLibrary` ASTC file(s) as
additional `--visual-asset-bundle` arguments *if locally present* to measure
standalone overlap, **not** to certify a mapping. No new online requests are
needed. Local fixtures are **private**: never commit/package them, copy them
into an issue, or send unredacted game responses to investigators. The CLI
produces only counts by default. It rejects missing/wrong source inputs and
refuses to overwrite an existing report.

For an explicitly authorized **numeric-only** investigation, add:

```sh
--show-unmatched-paint-interior-ids
```

This intentionally prints and optionally saves the distinct remaining numeric
IDs with occurrence counts and reason, separately for paint vs interior and
TNR-shaped vs other cars. It never includes member rows, names, player or crew
IDs, exact model keys, wheel strings, caliper/livery/color IDs or raw server
responses. Avoid this option for reports you plan to share. The previous
Dev24 counts-only JSON alone cannot recover those 11 missing IDs.

## Four evidence lanes

1. **Compatibility:** The `IncludeToCar` histogram and primary categories
   identify *what the source contains*, not an actionable vehicle eligibility
   rule. The unchanged native primary parser remains the label source, but no
   seven-candidate promotion occurs without independently confirming
   supplementary rules and corresponding in-game appearance.
2. **Paint/interior:** Unresolved values are split into `not_matched_in_six_sources`,
   `tnr_hit_outside_syntax_cohort` and `ambiguous_cross_library`. Each of
   these remains unresolved. Six-source comparison coverage totals are
   recomputed on the **same provided** fixture: never subtract counts from
   unrelated live snapshots or other source subsets.
3. **Wheels:** Check model-specific `MODEL_Wheel...` asset availability separately
   from the shape and length of the native wheel string. Check exact asset-code,
   asset-suffix, and Tuner Stars rim-name equality **only as coincidences**.
   Wheel-string encodings and model-specific bundle formats have not been
   decoded. The Tuner Stars rim library is *not* a universal wheel dictionary.
4. **Colors:** Standalone `CarColorLibrary` ID overlaps are exposed only as
   source coincidences; no roster decal number color, shape color, or zone
   field is mapped to official palette labels.
