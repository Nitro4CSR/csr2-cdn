## Print every member from the actual read-only server response

```console
python -m pip install -e .
python -m csr2cdn.crew_rp_verification --execute --print-member-values --expected-members 29 --reference-total 37448821 --reference-rank 257 --season-note "Manthey 911 Prestige Cup"
```

The command hides the PlayerID prompt and uses **only** the existing
`crews/checkUserCrew` and `crews/viewMembers` reads. It prints member nicknames,
levels, `cc_contrib`, profile `player_rp`, all-time RP when present, sorted by
`cc_contrib`, then computes the sum and difference versus the UI reference.
It does **not** print private member IDs, authorization headers or raw
response JSON, and never saves a file. Nonetheless **member names and scores
are printed** by explicit operator request; safeguard the terminal output.

Output `--format json` uses the same limited columns. The printed list rank is
**sort order by member contribution**, *not* the position of the crew in the
GCC leaderboard. A sum mismatch alone does not invalidate `cc_contrib`: the UI
screenshots and live response may have been captured at different times,
with members earning RP or changing crews.

## Optional supplied GCC response inspection

```console
python -m csr2cdn.crew_rp_verification --gcc-response-json local-gcc-response.json --format table
```

Accepts an *already acquired* GCC response JSON file, decodes `results` to
crew rank, crew name, `cc_rp`, all-time RP, and prints every decoded row. Add
`--execute --print-member-values` to the same invocation to compare the
returned crew's ID with those records, if the source file is genuine. This
command **does not retrieve GCC data** because its signed native request
path and season selector are not yet validated. Never paste authentication
material from raw captures. No invented leaderboard endpoint is used.
