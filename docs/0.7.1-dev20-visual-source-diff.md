# 0.7.1.dev20 — visual source refresh and missing-ID recheck

## Evidence and boundaries

The 2026-10-18 authorized Dev17 run returned 124/192 resolved visual-code
labels. The remaining 68 consisted of 29 roster wheel strings, 24 racing/decal
color/zone codes, and 15 direct paint (9), interior (3), and caliper (3)
library ID misses. Dev19 added an **opt-in** aggregate diagnostic for distinct
unmatched *numeric* IDs, but no such ID values were retained from Dev17.
Dev20 has **not** observed the values of these missing codes or performed any
new game or CDN requests.

The historical `Documents.zip` metadata confirms `CarCustomizationParameters`
defines separate `RacingNumberColor_Base` and `RacingShapeColor_Base` options,
while `CarAftermarketCustomisations` carries per-car default zone/color codes.
Neither block proves equality with `CarColorLibrary` IDs. The native
`CarTunerStarsRimLibrary` has Tuner Stars numeric IDs, whereas the roster sends
`car_wheel_name` as a string; no universal wheel-name equivalence is established.
**Do not** bind any of these four unverified fields automatically.

## New offline APIs

`compare_visual_sources(old_visuals, new_visuals)` produces a
`VisualSourceDelta` with `.paint.added`, `.paint.removed`,
`.paint.label_changed`, `.interior.zone_names_changed`, and all other decoded
slots. The key is exactly `(model_key, slot, code)` with no string/number
coercion. Renamed labels are distinguished from newly added IDs; unchanged
record ordering and file SHA values don't imply a new mapping. Reports contain
counts only; no player, model, label or ID values are emitted.

`recheck_visual_missing_ids(old_diagnostics, old_visuals, new_visuals)` accepts
only a previously opt-in `VisualGapDiagnostics.as_dict()` (or the
`visual_gap_diagnostics` section of a bulk report) containing a bounded
`unresolved_numeric_ids` list. It matches *global library IDs only*, since
model IDs were intentionally excluded from the private-safe diagnostic. Its
`.paint.newly_available_ids` and `.paint.still_missing_ids` are candidates for
new source coverage, not proof of UI accuracy. The unsupported wheel/color
joins are always excluded, even if new palette IDs overlap.

## Local command

No account credentials, game endpoints, automatic CDN downloads or file writes:

```bash
python -m csr2cdn.visual_source_delta_cli
```

To compare two locally downloaded generations of supported ASTC libraries:

```bash
python -m csr2cdn.visual_source_delta_cli \
  --before-bundle ./old/CarPaintLibrary.ASTC.1195 \
  --before-bundle ./old/CarInteriorLibrary.ASTC.1139 \
  --after-bundle ./new/CarPaintLibrary.ASTC.NEW_VERSION \
  --after-bundle ./new/CarInteriorLibrary.ASTC.NEW_VERSION
```

`NEW_VERSION` is a **placeholder**, not an invented CDN version. Select the
asset names and versions from a current asset database. Supplying only one
library in a generation is valid but *other* slots appear as added/removed;
for meaningful diffs, compare equivalent sets of source libraries.

To re-evaluate a **previously saved explicit numeric-ID opt-in** diagnostic,
append `--unmatched-report ./reviewed-private-gap-diagnostics.json`.
The CLI reports count-only results and never prints IDs or player details;
it does not turn unsupported joins into verified ones.

## Offline test gates

- Compare and recheck only typed, bounded local source records.
- Reject duplicate identifiers and malformed opt-in diagnostic reports.
- Treat raw ID zero as valid and separate interior zone-name drift.
- Never emit untrusted path strings, player names, raw wheel codes or visual
  names in the default report.
- Source ZIP, wheel, sdist and patch regressions must pass before distribution.

**Follow-up:** Obtain source-fresh asset versions and, only if a separate
private-safe authenticated diagnostic is approved, the actual missing numeric
IDs. Dev20 does not run that diagnostic or record additional live data.
