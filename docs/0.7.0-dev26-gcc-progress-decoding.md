Every observed object contains `crew_id` (string), `name` (string), `rank` (integer), `score` (integer), `logo` (object). The operator's earlier own-crew snapshot was 37,448,821 / rank 257, and the dev23 member contribution sum was 37,463,129 at an earlier time. **Matching ranks or similar names do not prove crew identity.** The backend crew_id must match the own-crew ID. Neither the response nor the supplied diagnostic identifies its active season; score units still require same-time in-game checking. The native *progress* row parser was not fully recovered; don't mislabel this typed wire decoder as verified native field interpretation.

## Implementation

* New `GCCProgressCrewScore` and `GCCProgressCrewScores` typed response objects parse observed `scores` records. Strict nonnegative integer scores, positive numeric ranks, text crew IDs/names, bounded rows, unique IDs. There is **no implicit conversion from `score` to `cc_rp` or `RP_allTime`**.
* `make_gcc_progress_report` performs **exact ID equality** between own-crew membership `crew_uid` and GCC row `crew_id`, never using rank or display name as a proxy. Crew IDs, credentials and raw replies are not printed.
* A successful wire decode reports `gcc_progress_rows_decoded_season_unverified` and the own crew's score/rank, if a single matching ID is found; it shows numeric difference from the operator's historical UI snapshot, not a same-time accuracy proof. Full crew name/rank/score rows print only with `--gcc-print-score-candidates`. All results remain explicitly season-unverified.
* If the response has an unknown/invalid scores shape, fall back to dev25 safe diagnostics and nonzero exit. A valid wire decoder returns zero exit even though **seasonal Crew RP release remains blocked**; status flags explicitly separate syntax from semantics. The older results decoder remains intact.
