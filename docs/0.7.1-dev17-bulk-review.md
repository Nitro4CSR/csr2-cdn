# 0.7.1.dev17 — One-round bulk validation and operator review

## Scope and safety

This is a **prepared** investigation of 0.7.1 experimental features. The published
0.7.0 baseline is unchanged. Default execution makes **zero network requests**.
A later explicit `--execute` performs one `crews/checkUserCrew`, one
`crews/viewMembers`, one proven GCC common window, and one bounded *experimental*
GCC range. No auto-pagination, retries, metadata fetches, save-game writes, or
social-account lookups. An interactive player-ID prompt is required and hidden.

Read-only sources can be stale or change between calls: this is not a consistent
transaction. A returned crew-stat field is **not automatically validated** by
its name or presence. `crew_rp` must never be substituted for seasonal member
`cc_contrib` or the exact-ID-matched GCC `score`.

## Offline dry run

```bash
python -m csr2cdn.crew_bulk_validation
```

The dry run prints the planned four operations and the default experimental range
`top=20`, `before=10`, `after=10`, `offset=0`, but performs none of them.

## Prepared combined command (do not execute until the bulk test is approved)

Run from a directory containing your original source assets, and supply these
local file paths. They are not included in the package. Use `MEDIUM` by default;
choose `SHORT` or `LONG` with `--car-name-style`.

```bash
python -m csr2cdn.crew_bulk_validation --execute \
  --top 20 --before 10 --after 10 --offset 0 \
  --translation-unityfs Localisation_EN.ASTC.6312 \
  --visual-asset-bundle CarPaintLibrary.ASTC.1195 \
  --visual-asset-bundle CarLiveryLibrary.ASTC.1042 \
  --visual-asset-bundle CarInteriorLibrary.ASTC.1139 \
  --visual-asset-bundle CarCalliperLibrary.ASTC.1004 \
  --visual-asset-bundle CarColorLibrary.ASTC.594 \
  --visual-asset-bundle CarTunerStarsRimLibrary.ASTC.434 \
  --visual-asset-bundle CarFlagLibrary.ASTC.532 \
  --visual-asset-bundle CarRacingNumberLibrary.ASTC.524 \
  --visual-asset-bundle CarLicensePlateLibrary.ASTC.580 \
  --visual-asset-bundle CarWrapLibrary.ASTC.677 \
  --visual-asset-bundle CarLiverySetLibrary.ASTC.661 \
  --visual-asset-bundle LiveryZonesSetLibrary.ASTC.670
```

Optional `--show-stat-values` prints *crew* values and member aggregates. The
`--show-members` flag prints per-member names, stats, and vehicle details:
**avoid it when sharing reports publicly**. `--print-gcc-entries` prints crew
names/ranks/scores, another explicit opt-in. The default report holds only
counts, booleans, candidate statuses, ranks/scores of the own crew and source
coverage; **check the report before sharing it**. No player/crew IDs are emitted.

## Optional UI reference comparison

Use a local JSON file to compare the game's own-crew rank, score, and crew count
as close as possible to the capture time:

```json
{
  "format": "csr2cdn.crew-bulk-ui-reference.v1",
  "own_crew_rank": 123,
  "own_crew_score": 4567890,
  "crew_member_count": 29
}
```

Those values are **examples**, not asserted observations. Pass the file as
`--ui-reference-json my-own-ui-reference.json`. Unknown fields, IDs, names,
invalid/oversized values and boolean-as-number inputs are rejected. Reference
checks report `agrees`, `differs_review_snapshot_timing`, `not_observed`, or
`not_supplied`; agreement means only numeric equality to the supplied reference,
**not** independent UI confirmation or timing equality. Local files are
checked *before* the authenticated reads, avoiding unnecessary requests if a
bundle or reference is invalid.

## Result interpretation

Read the `review.features` object in the JSON result. It records separately:

- `roster`: returned rows and whether the IDs/count agree with the own-crew
  response. This cannot prove real-world completeness independently.
- `crew_rp_vs_gcc`: exact contribution sum versus common GCC after freshness,
  coverage and read-gap guards. A non-atomic mismatch can mean live changes.
- `gcc_expanded_range`: row growth and ID-matched overlap. **Expanded rows are
  not proof of full pagination**, and unchanged rows might be server clamping.
- `crew_stats`, `member_stats`, `vehicle_details`, `vehicle_appearance`: counts
  of observed fields; their numerical meanings are candidates until UI review.
- `translated_car_names` and `visual_names`: the number of exact local asset
  labels resolved on roster vehicles. No invented wheel/rim, color or wrap join.

`review.automatic_feature_acceptance` is always `false`. Results remain
candidate evidence until manually compared and assigned **keep**, **fix**, or
**prune**. If one GCC request errors, the other read plus optional data remain
visible as a partial report. The 0.7.1 release and cross-platform CI remain
separate gates.
