# Dev51 — crew paint JSON handoff in CSR2 6.8.0

This is an **offline, APK-native** audit. It uses `global-metadata.dat` and
`libil2cpp.so` from an operator-supplied APK; the original APK and any crew
responses remain private. Source, tests, and redacted findings can be shared.

## Reproduce

```bash
python -m csr2cdn.dev51_crew_paint_parse \
  --apk CSR2_6.8.0.apk \
  --received-report dev38-received-unmatched-ids.json \
  --output dev51-native-crew-paint-handoff.json
```

The `--received-report` is optional, and accepts only Dev38's **redacted
aggregate** report, not a raw crew response. No CDN, auth, or game request is
performed; report files are created exclusively and never overwritten.

## Native witness (APK 6.8.0)

1. IL2CPP metadata literal #29343 is exactly `car_paint_id`.
2. In `PlayerCrewMember.FromJSONDict` (RVA `0x34a3d78`), ARM64 at RVA
   `0x34a42b4` loads a relocated metadata-usage pointer. The referenced
   encoded usage `0xa000e53f` resolves to literal #29343.
3. The method tests for this JSON key and, if present, reads its integer
   into stack slot `SP+0x94` (JSON read call at `0x34a4314`).
4. Later the same native method loads `W1` from `SP+0x94` and calls
   `CrewMemberCarInfo.SetPaint` at `0x34a4da8`.
5. `CrewMemberCarInfo.SetPaint` at RVA `0x35793b4` is a direct
   `STR W1,[X0,#0x20]; RET` integer store. This matches the managed
   `CarPaintIndex` property.

The program checks the method pointers via the compiled method-token table,
checks relocated metadata usage against the **actual literal bytes**, checks
the bounded ARM64 call and stack-slot flow, and fingerprints native bodies.
It refuses to report a verified witness if those pieces are absent or
ambiguous.

This directly supports the **client's crew JSON integer → paint-index-named
model field** handoff. It does **not** prove what the server stores internally,
how that number is chosen by a particular vehicle, whether one should use a
car-specific `CarPaintIDs` ordering, or that one can convert every received
number using the global paint library.

## Impact on known observations

- Current Dev38: 29 paint values; 20 belong to standard/TNR global paint
  source IDs, eight are zero, and one is 15.
- **0 → Transparent** remains the operator-approved *display label*, not a
  newly verified client default or transparency effect.
- **15** remains unresolved. We have now verified the client's JSON handoff
  into an index-named field; an actual car-specific ordering is still needed
  before index 15 can be assigned a native paint name.
- Paint/interior/caliper resolution, production mapping tables, and all
  other decoders are unchanged.

## Limits and next technical target

Find the actual `CarPaintIDs` list construction and how the selected car
translates `CarPaintIndex` into `CarPaintLibrary.GetIDByIndex` or a
model-specific paint-ID list. Validate the list for the affected car locally
against cached public assets, without exposing player identities. Do not
promote index-based labels based on numeric coincidences alone.
