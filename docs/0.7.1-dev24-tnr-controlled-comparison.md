# Dev24: standard vs. Tuner Stars visual source comparison

This is a **single, bounded, read-only game-data test**, not the 0.7.1 bulk
validator and not a pagination test. No calls occur without `--execute`.
Run first without that flag to confirm zero network requests.

## Six local Android ASTC sources

The controlled comparison requires **all six** decoded native sources:

- `CarPaintLibrary.ASTC.1195`, `CarInteriorLibrary.ASTC.1139`, `CarCalliperLibrary.ASTC.1004`
- `CarTunerStarsPaintLibrary.ASTC.412`, `CarTunerStarsInteriorLibrary.ASTC.393`, `CarTunerStarsCalliperLibrary.ASTC.382`

It also requires the user-supplied `asset_database_6_8_0_Release` (or
corresponding fresh database). The script validates the local files and their
native schemas **before** prompting for the PlayerID or making a gameplay
request. No game asset is bundled in the Python distribution.

## Dry run

```sh
python -m csr2cdn.tnr_visual_probe --compare-standard-tnr
```

## Future operator-authorized one-shot test

From the directory containing the six libraries and asset database:

```sh
python -m csr2cdn.tnr_visual_probe \
  --execute --compare-standard-tnr \
  --asset-database asset_database_6_8_0_Release \
  --visual-asset-bundle CarPaintLibrary.ASTC.1195 \
  --visual-asset-bundle CarInteriorLibrary.ASTC.1139 \
  --visual-asset-bundle CarCalliperLibrary.ASTC.1004 \
  --visual-asset-bundle CarTunerStarsPaintLibrary.ASTC.412 \
  --visual-asset-bundle CarTunerStarsInteriorLibrary.ASTC.393 \
  --visual-asset-bundle CarTunerStarsCalliperLibrary.ASTC.382 \
  --output tnr-dev24-safe-report.json
```

**Exactly two planned read-only gameplay calls:** `crews/checkUserCrew` to
identify own crew, then `crews/viewMembers` for its roster. A separate auth
exchange may occur. No GCC queries, profile modifications or CDN downloads.
The PlayerID prompt is hidden and is not included in the report.

For a zero-network synthetic/offline replay, replace `--execute` with both
`--own-json <fixture>` and `--members-json <fixture>`. Do not share raw fixture
responses or unredacted player data.

## How to read the report

`standard_tnr_comparison.cohorts` separates model keys matching TNR syntax
from other/unknown models. Its paint/interior/calliper sections contain:

- `present`, `standard_matches`: baseline standard source ID matches
- `new_tnr_id_candidates`: standard misses with a source ID match **on a TNR-looking model**
- `still_unresolved`: fields that remain unresolved, including suppressed
  non-TNR candidate matches or ambiguous source collisions
- `candidate_matches_after`: standard matches plus admissible TNR ID candidates
- `tnr_id_candidates_outside_tnr_models`: numeric overlap on other models;
  **not promoted to a name mapping**
- `ambiguous_cross_library_ids`: source-ID collision, not counted as matched

The report includes source library names but **no player names, IDs, car model
strings, raw cosmetic IDs or wheel strings**. Do not enable
`--show-unmatched-numeric-ids` for this initial test. The report does not
save raw network responses. It refuses to overwrite an existing report.

A candidate-match improvement is evidence for the TNR-source hypothesis,
not proof of actual in-game appearance: supplementary Tuner Stars eligibility
rules are not completely decoded, and the model classifier uses syntactic
patterns. Wheels and decal colors are outside this comparison, and remaining
standard source misses do not automatically imply newer CDN files are needed.

Review the counts and compare representative visuals manually before accepting
any automatic cosmetic labels. If the TNR candidate count is zero, investigate
other libraries/IDs rather than guessing names. No source-level changes or
pruning occur in the live probe.
