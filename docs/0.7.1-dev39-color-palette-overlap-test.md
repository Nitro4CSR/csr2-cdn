# 0.7.1.dev39 — Test whether received paint IDs overlap `CarColorLibrary`

## Why this matters

The Dev38 authorized fresh 29-vehicle roster reported exactly two **numeric paint
IDs absent from both standard and TNR paint libraries**: `0` (8 occurrences:
1 TNR-syntax, 7 other) and `15` (1 occurrence: other). Its reference database
was 34011 on `6_8_0_Release`. All interior and calliper IDs resolved as source
IDs. This was **not** the Dev24 historical snapshot.

A separate, already-supported source, **`CarColorLibrary` (singular)**, is a
palette with `CarColors` entries: each entry has a numeric ID, `NameID` and
RGBA value. Dev14 verified 11 native records in `CarColorLibrary.ASTC.594`
(older input, not necessarily the current one). The source decoder retains
unnamed records while its named-label export intentionally excludes them.

**This source is not `CarPaintLibrary`.** An ID overlap does not establish
that `car_paint_id` refers to the palette, or that numeric `0` is a default.

## Execute using Work (no game access)

Upload the Dev39 source ZIP and the sanitized `dev38-received-unmatched-ids.json`
into the same Work environment. With Python and permitted network access:

```shell
python -m csr2cdn.dev39_color_palette_overlap \
  --received-report dev38-received-unmatched-ids.json \
  --online --branch 6_8_0_Release \
  --output dev39-color-overlap.json
```

This executes at most **three public read-only HTTPS GETs**, all under the
configured CSR2 public CDN origin:
1. `asset_database_6_8_0_Release.version`
2. `asset_database.<advertised-version>.json`
3. `ANDROID/ASTC/CarColorLibrary.ASTC.<indexed-version>`

No account authentication, crew service call, gameplay read/write, raw roster
storage or manual game comparison is involved. Redirects, oversized objects,
unauthorized branches and changed array schemas fail closed.

The report records the exact decoded presence and optional source label for
**each received unmatched paint ID**, plus source SHA-256 and indexed version.
The report is an explicit research artifact and contains no PlayerID, player
name, crew identifier, model identifier or raw game response. If the public
asset data has changed since Dev38, the report flags that database drift.
Only share the generated report, not private credentials or raw roster data.

## Replay an existing local source (0 network requests)

```shell
python -m csr2cdn.dev39_color_palette_overlap \
  --received-report dev38-received-unmatched-ids.json \
  --color-bundle ./CarColorLibrary.ASTC.<real-version> \
  --output dev39-color-overlap-offline.json
```

The local source must be a verified original bundle. Offline mode can compute
its SHA-256 and parse IDs, but cannot establish its database/version lineage;
those fields remain null rather than guessed.

## Evidence rules

- If ID `0` or `15` is **present** in `CarColorLibrary`, that is **only a numeric overlap across distinct namespaces**.
- If **absent**, the color-palette hypothesis is unsupported for that ID in the checked library version.
- `palette_name` may be null even for a present record (some native palette records have blank `NameID`).
- Zero is always treated as an integer ID; it is **not** interpreted as a default or unset instruction.
- Existing production paint mappings, TNR decoder, color and wheel eligibility remain untouched.
- Tests use synthetic UnityFS and HTTP responses; no successful actual Dev39 CDN read is claimed in this environment.
