# 0.7.1.dev15 — Offline visual library asset planning

This development increment does **not** decode more native libraries. It makes the
next operator-supplied Android ASTC asset fetches deterministic and auditable.
The original 6.8.0 asset database is the sole source of codes, versions and
quality-specific byte counts. URLs are constructed using `CDN.asset_url`,
not copied from unverified examples. No network access occurs while planning.

```bash
python -m csr2cdn.visual_asset_planner \
  --asset-database asset_database_6_8_0_Release --show-urls
```

Default: seven still-unknown visual libraries, Android ASTC. Select an exact
slot with `--slot tuner_rim` or `--slot flag`; repeat for multiple slots.
Use `--all` to include the five source-decoded paint/livery/interior/caliper/
color libraries. `--quality High` is an **explicit opt-in** to an alternate
Android CDN quality and does not imply iOS compatibility. The user previously
confirmed that Android uses ASTC; the SDK's default quality is also ASTC.

`plan_visual_assets_from_file(path)` returns a `VisualAssetPlan` with immutable
`VisualAssetCandidate` entries. Each has `slot`, `code`, `version`,
`filename`, `size_bytes`, `url`, `decoder_status` and `roster_join_status`.
`absent_slots` is explicit. Unsupported quality/platforms and unsafe versions
fail closed. No user IDs, authentication tokens, snapshots, or private members
are read or included.

These are library-naming-based *candidates*, not confirmed roster field joins.
`CarTunerStarsRimLibrary` is scoped to Tuner Stars; it is not a proven global
wheel/rim library. Roster `car_wheel_name` is a string, and no numeric
Tuner Stars rim ID relation has been verified. The decal and license-plate
code relationships likewise remain unverified. Dev15 does not auto-bind them.

Five previously uploaded libraries are decoded and continue to work through
`load_visual_libraries_unityfs`: paint, livery, interior, calliper, color.
Color ID 9 has no name and stays unresolved. The global library IDs and
option-specific crew appearance data must not be conflated without evidence.

The manifest is tied to the **provided 6.8.0 database**, not a guarantee of
current CDN availability. No CDN HTTP responses, new native library source
files, online gameplay tests, or CI runs are claimed.
