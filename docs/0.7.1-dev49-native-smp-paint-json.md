# Dev49 — Native SMP paint JSON roundtrip, separate from crew-service wire

## Verified on CSR2 6.8.0 APK

Using IL2CPP v31 managed method tokens and the verified `Assembly-CSharp.dll` ARM64 pointer table, Dev49 inspects the actual method bodies **offline**. There are no game requests, CDN downloads or authentication.

- `SMPHostInfo.SerializeToJson` (`0x3432534`): ARM64 `LDR W2,[X19,#0x68]` at `0x3432a4c`, followed by key preparation and a function call that takes the integer as an argument at `0x3432a60`. The method is the SMP host JSON serializer.
- `SMPHostInfo.SerializeFromJson` (`0x3433440`): after a JSON integer read call at `0x3433a04`, immediately stores `W0` to `[X19,#0x68]` at `0x3433a08`. There is no ID/index conversion *between this call and this store*.
- The getters and setters for `SMPHostInfo.AppliedPaintIndex` (`0x3436fb8` and `0x3436fc0`) directly read and write field offset `0x68`.

The report contains relative native virtual addresses, bounded SHA-256 method-span hashes and witnessed instruction offsets. The analyzer checks exact little-endian ARM64 opcodes with adjacent call context; it refuses to infer semantics when witness bytes are missing or duplicated. Neighboring pointers limit extracted byte spans but do not prove native function boundaries. This is a **SMP-host information serialization path**, not necessarily the crew-service endpoint that returns `car_paint_id`.

## Crucial distinction

The APK has at least these distinct paths:

1. `CarGarageInstance.AppliedPaintIndex` copied to `CrewMemberCarInfo.CarPaintIndex` (Dev48 crew snapshot).
2. `SMPHostInfo.AppliedPaintIndex` serialized and read back as an integer (Dev49 SMP JSON path).
3. Native paint-library `GetIDByIndex` and `GetIndexByID` methods for standard/TNR sources.
4. The remote crew-service response's `car_paint_id`, which **has not been traced to path 1 or 2**.

The source-library exact-ID matches on 20/29 crew rows should not be discarded. The one received paint value `15` remains unresolved, and a per-car index-to-ID conversion is **not supported without discovering the car's ordered paint-ID list and the actual wire mapping**. Operator-approved `0 → Transparent` display label remains separate from native semantics.
