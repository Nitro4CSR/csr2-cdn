# Dev43 — local metadata key-path triage against 14 roster fields

This continues the Dev41 field-source provenance work and Dev42 JSON shape audit. It answers a **narrow** research question: *Do existing, locally saved JSON customization metadata blocks contain sampled key paths whose spelling resembles one of the 14 observed crew roster wire fields, and are those values represented with the expected primitive type?*

A path match **does not** establish that a key is a foreign key, a paint-library ID, a default value, a wheel identifier, or a valid vehicle option. It is not NMG decoding. The separate binary APK `.metadata` blocks remain opaque, and JSON `.meta` cache blocks are a different source format. Production visual decoding and ID trust policy remain unchanged.

## Offline report from the existing source baseline

```bash
python -m csr2cdn.dev43_field_path_triage \
  --provenance-report dev41-field-source-provenance.json \
  --output dev43-field-path-triage.json
```

With no local metadata-cache files available, the report explicitly marks analysis incomplete and reports zero *observed* field candidates; it **does not** imply that the underlying game has no matching schema. No network or gameplay requests occur.

## Analyze previously saved JSON metadata cache in Work

```bash
python -m csr2cdn.dev43_field_path_triage \
  --provenance-report dev41-field-source-provenance.json \
  --metadata-cache-dir ./saved-metadata-cache \
  --output dev43-local-redacted.json \
  --private-candidate-paths-output dev43-private-candidate-paths.json
```

- `--metadata-cache-dir` must refer to an existing local directory with any of the seven allowlisted `<BlockName>.meta` JSON files. **It never synchronizes the cache** or fetches additional data.
- The **redacted report** includes candidate counts per roster field, counts of sampled type agreements, source-block names, a source SHA-256 per available block, sampling limitations, and explicit `false` verification flags. It contains no metadata keys or values.
- The **separate PRIVATE file** includes matching JSON key paths and sampled types, not values. Key names *may themselves identify private records*. Keep it local, review before sharing and do not publish it. Both outputs require a new, non-symlink destination and are created with restricted file permissions where supported.
- Traversal uses Dev42's bounded JSON inspector (16 items per array, 120 sampled paths per block, depth 9 and 50,000 node budget). The analysis is therefore **not exhaustive**; neither a zero match nor a match is a conclusive schema result.

## Lexical classifications

1. `exact_wire_key_spelling`: a normalized JSON leaf key spells the entire wire field, e.g. `CarPaintID` and `car_paint_id`.
2. `without_car_prefix_spelling`: key spells a wire field without its leading `car`, e.g. `PaintID`.
3. `related_key_token_only`: shared explicit word token such as `Wheel`, not a numeric join. This grade is intentionally weak and can produce false positives.

A type-agreement count merely checks `integer` or `string` to match the Dev41 wire type. No source values are examined or compared to the roster, and no inferred ID fields are populated. The comparison requires the **original Dev41 JSON report** with its 14 fields and expected wire types; report version/source hashes are carried as provenance rather than confused with verified runtime schemas.

## Evidence required to progress

For paint ID 15, seek an independently decoded native structure containing both a *semantically established* paint-ID reference and a car-specific applicability rule, supported by corresponding source records. `0 → Transparent` remains an **operator-approved display label** from the Dev39 palette overlap, not an established native paint foreign-key join. ## Validation

The added tests use synthetic JSON only. No original game source binary bundles, metadata caches, APKs, credentials, or roster responses are shipped in the source ZIP or wheel. This is an investigation build, not a release candidate.
