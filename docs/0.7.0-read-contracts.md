# CSR2 0.7.0: reconstructed read contracts (unreleased / unverified live)

## Status and scope

This is an **offline, internal implementation milestone** on the verified 0.6.0
baseline. It does not declare version 0.7.0 ready. There are no public Python
service classes, new CLI commands, save operations, upload methods, or shipped
private downloader files. Only three native-traced read builders are enabled
inside `csr2cdn._service_reads`. All three are still **unverified live**.

### Evidence (CSR2 Android 6.8.0 IL2CPP ARM64)

The verified request builder method `PlayerCrewNetwork.FetchCrewMembers`
(RVA `0x350203c`) loads string usages resolved from `libil2cpp.so` and
`global-metadata.dat` for `crews/viewMembers` (literal 30565), `crew_uid`
(literal 30523), `app_ver` (literal 28177), and the operation description
`Get Crew Member List` (literal 9889). At `0x35021a8`, it invokes
`WebRequestQueue.StartCall` with request type 3, and supplies the crew UID
provided to the native method. This identifies the *crew members* route;
it does not prove a live response or other hangout features like presence/chat.

`ShowdownLeaguesLeaderboardProvider.FetchLeaderboardProgress` (RVA
`0x2ead984`) references `leaderboard/{0}/view` (literal 35501) and wire keys
`app_ver`, `top`, `after`, `before`, `offset`, passing type 5 at `0x2eadc18`.
The `top` wire key is omitted when the native range's top value is `INT_MIN`.
`FetchLeaderboardPreview` (RVA `0x2eadd24`) references
`leaderboard/{0}/preview` (literal 35496) and includes an extra `score` key;
its `StartCall` occurs at `0x2eadfe4` with type 5. Both use an already
resolved `leaderboardName`; **an event ID by itself is not sufficient at this
layer**. These methods are for **Showdown Leagues**, not verified to cover
classic Showdown event trophy rankings or Prestige Cup.

`PlayerCrewMember.FromJSONDict` (RVA `0x34a3d78`) directly reads keys
`player_uid`, `zid`, `name`, `role`, `current_car`, `car_pp`, `car_ep`, and
numerous car paint/livery/wheel/customization fields. The client model
`FetchCrewMembersResponse` declares `crewUID` and `crewMembers` fields.
These are *potential* decoded fields; response wrapper shape, optionality,
privacy rules, and successful field population have not been verified live.
No response-value fixtures or exact parser are invented in this release stage.

## How to inspect the offline contracts

```python
from csr2cdn._service_reads import StandingRange, crew_members_contract, showdown_standings_contract
crew = crew_members_contract("YOUR_CREW_UID", app_version="6.8.0")
# Crew: crews/viewMembers, request category 3, parameters crew_uid and app_ver
showdown = showdown_standings_contract("RESOLVED_BOARD_NAME", StandingRange(after=0, before=0, offset=0, top=10))
# Showdown Leagues: leaderboard/RESOLVED_BOARD_NAME/view, request category 5
```

These numeric values in the Showdown example are **illustrative inputs**.
The APK's compiled `LeaderboardRecordRange` initializers establish actual
native presets: `.common()` = `top=10, after=5, before=5, offset=0` (RVA
`0x2bdc660`, ARM64 constant at `0xf2b2a0`); `.preview()` = `top` omitted,
`after=4, before=4, offset=0` (RVA `0x2bdc674`, at `0xf29520`); and
`.top3_and_you()` = `top=3, after=0, before=0, offset=0` (RVA `0x2bdc688`,
at `0xf2b750`). Use `StandingRange.common()` when that specific client range
mode is desired. The preset alone does **not** establish a server cursor model. No network or authentication is triggered
by these functions. `prepare_read_contract` accepts only the three allowlisted
operations, and produces a signed, but unsent, request after a session has
been obtained. It will never sign unknown or save-game routes.

## Read-only API and CLI

The package now exposes `CSR2Services` for crew, Showdown, and Prestige Cup
reads, plus separate legacy Showdown Leagues compatibility methods. Each method
has an offline `prepare_*` form and a network-enabled `get_*` form.

```console
csr2cdn services crew YOUR_CREW_UID
csr2cdn services showdown --leaderboard-name RESOLVED_NAME
csr2cdn services showdown-leagues --leaderboard-name RESOLVED_NAME
```

No requests are sent without explicit `--execute`. The CLI never logs the
service session, credentials, or raw server responses in error paths.
See [offline preflight](0.7.0-offline-showdown-preflight.md) for metadata-based
Showdown discovery and safe failure scenarios. Details for *regular* Showdown
and Prestige Cup remain provisional and require a final live test.
