# Dev41 — Field-to-source provenance and source-validity gates

**Scope:** offline code inspection and evidence reconciliation. Uses the operator's existing Dev36 source summary, Dev38 sanitized roster coverage and Dev39 color palette overlap report (database **34011**). Does **not** decode the NMG customization blocks, perform live gameplay reads or fetch more source binaries. Nothing is promoted to a trusted production mapping.

## Evidence levels must stay separate

| Claim | Where established | What it does **not** prove |
|---|---|---|
| Source asset is listed/versioned | Validated CDN asset index in Dev36, only for six supplied library names | Roster field correspondence |
| Native primary array decoded | `visual_library_bundle._SPECS` and ASTC parsing logic | Eligibility for a specific car |
| Exact roster ID is present in candidate source | Dev38 comparison of fresh roster IDs against the six source libraries | Semantic identity of similarly numbered fields |
| Same namespace is demonstrated | Requires an explicit field relation in independently understood native metadata | **Not established** by any current evidence |
| Vehicle eligibility / visual appearance | Requires independent game or native mapping evidence | **Not established** by matching ID or guessed category |
| User-approved display alias | Paint ID `0` → `Transparent` (requires explicit option plus Dev39 report) | Native `car_paint_id` → `CarColorLibrary` correspondence |

`CarWrapLibrary`, `CarLiverySetLibrary` and `CarColorLibrary` remain valid **standalone source libraries**, not substitute dictionaries for paint. The inventory contains the seven allowlisted `CarCustomizationParameters`, `CarAftermarketCustomisations`, `CarLiveriesMatrix`, `CarPresets`, `CarAdditionalVisuals`, `AftermarketConfig`, and `HypermodMaterialsConfig` APK blocks, but none is semantically decoded.

## Real operator-report evidence preserved

- Dev36 reports six source libraries under `6_8_0_Release`, database **34011**.
- Dev38 reports **paint 20/29 exact-ID present**; missing paint `0 × 8` and `15 × 1`. Interior and caliper are **29/29** present.
- Dev39 confirms `CarColorLibrary` palette ID **0 = Transparent**; ID 15 not present in that separate palette. This does not establish a native paint-color join.
- A user-approved `Transparent` label can be shown through `--approve-transparent-zero`, but is separately identified as an *operator alias*; absent that option no alias is applied.
- Original game source bundles and APK metadata were not supplied. All source associations remain annotations based on inspected source code, not fresh native schema decoding.

## Corrected API semantics

`VisualAssetCandidate.name_mapping_verified` no longer conflates `decoder_status == "decode_supported"` with semantic mapping verification. It returns `True` only for an explicit `roster_join_status == "verified_roster_join"`. The built-in source list has **no such accepted status**, so all built-in candidates return `False`. Use `native_schema_decoded` for whether the native decoder exists, and `roster_id_match_candidate` for observed-numeric-ID research leads.

This is a **behavioral correction** to a previously misleading boolean. Existing consumers that interpreted the old flag as decoder support should migrate to `native_schema_decoded`.

## Command

```bash
python -m csr2cdn.dev41_field_source_provenance \
  --source-summary dev36-summary.json \
  --received-report dev38-received-unmatched-ids.json \
  --palette-report dev39-color-overlap.json \
  --approve-transparent-zero \
  --output dev41-field-source-provenance.json
```

- No network code path; no authentication or original crew payload required.
- Output must be new; private-file writing is no-overwrite and owner-only on POSIX.
- Report validates branch/version/source hashes for Dev36–38 and requires a same-branch/version palette for Dev39. It does not revalidate original asset bytes in this environment.
- It reports sources as candidates, not verified mappings. `--approve-transparent-zero` requires an actual matching palette report.

## Next research gate

A credible new source-to-field link requires the original native asset metadata or type tree with a **source field path**, **ID type**, **parent record**, **joining key**, **asset version/hash**, and a tested relationship to the roster field. `CarCustomizationParameters` and `CarAftermarketCustomisations` are logical first targets. Without that material, do not fabricate a decoder or rely on incidental cross-library numeric overlap. No additional authenticated roster reads are needed for this stage.
