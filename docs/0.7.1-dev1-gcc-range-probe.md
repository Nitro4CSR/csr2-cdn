# 0.7.1.dev1: bounded GCC leaderboard range investigation

## Baseline and safety

The published **0.7.0** release continues to use the established `leaderboard/crew-champs-v2/viewcrew` read with native `StandingRange.common()`, wire parameter order:

`app_ver`, `top=10`, `after=5`, `before=5`, `offset=0`.

CSR2 6.8.0's *generic standings serializer* accepts all four integer range inputs. The GCC current-progress call site was observed using the common range. Thus **the presence and wire order of those parameters do not prove that alternate GCC ranges or offset pagination are honored**. No new endpoint, upload, saved-game write, automatic crawl, or persistent authentication was introduced.

## New opt-in API

```python
from csr2cdn import CSR2Services, StandingRange

# This only creates a validated request description. Never sends requests.
with CSR2Services("YOUR_PRIVATE_PLAYER_ID", allow_network=False) as svc:
    contract = svc.prepare_gcc_progress_range(
        StandingRange(top=20, after=10, before=10, offset=0),
        exploratory=True,
    )
    print(contract.route, dict(contract.params))

# After separate authorization, construct with allow_network=True and call
# get_gcc_progress_range(..., exploratory=True) for one typed read.
```

The stricter experiment input bounds are: `top` 1–50, `before` and `after` 0–30, `offset` 0–1000, combined top+before+after <=100. These are **local safety limits**, not proven server limits. `offset` is not assumed to mean a global page cursor. The verified `get_gcc_progress_response()` call is unchanged.

## Offline-first diagnostic CLI

```bash
# Default: inspect intended request, zero network calls
python -m csr2cdn.gcc_range_probe

# Already captured JSON from a private, authorized source: no network
python -m csr2cdn.gcc_range_probe --fixture-json local-gcc.json --top 20 --before 10 --after 10

# Compare two existing replies by crew ID without disclosing crew IDs
python -m csr2cdn.gcc_range_probe --fixture-json later.json --compare-json earlier.json

# ONLY WHEN explicitly authorized to test: one opt-in GCC read
python -m csr2cdn.gcc_range_probe --execute --match-own-crew --top 20 --before 10 --after 10 --offset 0

# Allow printing crew names and scores (private operator review)
python -m csr2cdn.gcc_range_probe --execute --match-own-crew --print-entries
```

`--match-own-crew` causes one additional `crews/checkUserCrew` read. Without it, a single GCC read is issued after portal authentication. Values in a fixture file are read but never saved by the package; JSON response fields are sanitized by default. `--print-entries` deliberately outputs crew names/scores/ranks, never crew IDs, raw responses or authentication material. The CLI requires an interactive terminal for authenticated reads.

## Acceptance criteria for a future live probe

- Verify whether top >10 changes the server's global-top result count, and whether ±10 changes the own-crew neighborhood.
- Verify stable crew IDs, rank/score equality across overlapping common and exploratory reads. Differences may reflect sequential non-atomic updates.
- Compare a nonzero offset with offset=0 before making any pagination or absolute-rank interpretation.
- Verify response size and identify whether `cardinality`, `bucket`, `tier` represent population/scope before exposing such claims.
- Keep both the **complete leaderboard** and **active-season identifier** unverified until explicitly demonstrated.

All tests in this build are offline. No authenticated test or server reset is claimed.
