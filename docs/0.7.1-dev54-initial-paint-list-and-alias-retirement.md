# Dev54 — Initial paint-list constructor and setup (offline native witness)

Client: supplied CSR2 6.8.0 Android IL2CPP APK. The CLI verifies full native function SHA-256 fingerprints and instruction-level witnesses. No CDN/gameplay requests or private crew reads are performed.

## New native evidence

- `CarVisuals..ctor` at `0x3819978` constructs a list and stores it at object offset `0x70` (instruction `0x3819acc`). This is a **car-local** paint-ID collection.
- `CarVisuals.Setup` at `0x380275c` reads vehicle visual configuration at instance offset `0x168`, tests a field at visual-data offset `0x1c` against `0x7fffffff`, and on a conditional path appends the value to the list at `CarVisuals + 0x70` (`0x3802aa8`). A second branch also appends an ID at `0x380309c`. The full ordered list cannot be reconstructed statically from these instructions alone.
- Within `CarVisuals.Setup`, the garage instance's offset `0x6c` is read as a selected paint index (`0x3803680`) and the selected index is written to `CarVisuals.CurrentPaintIndex` at offset `0x11c` (`0x380369c`). Another branch can adjust the garage index to the new list's last position (`0x38036f4`–`0x380370c`).
- `CarGarageInstance.get_OriginalPaintIndex` reads a **different** garage offset (`0x70`), not the selection field at `0x6c`.
- The car-local list can be populated in setup and subsequently affected by aftermarket additions (Dev53). Existing paint IDs can be appended as options, so the global paint library order alone is not an adequate index conversion.
