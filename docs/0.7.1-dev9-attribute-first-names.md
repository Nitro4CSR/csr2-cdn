# 0.7.1.dev9: Attribute-first game car names

## Contract

Car-name source: decoded original CSR2 localisation UnityFS asset; source
strings are trimmed only at their outer whitespace for display. The preferred
name form is **MEDIUM**. The package never uses SHORT or LONG as fallback
for an absent MEDIUM entry.

```python
from csr2cdn import load_localisation_unityfs

translations = load_localisation_unityfs("Localisation_EN.ASTC.6312")
car = translations.match("Porsche_Manthey911GT3RSRewardRecycled_2024")

car.name                    # string-compatible MEDIUM text
car.name.long               # LONG variant
car.name.short              # SHORT variant
car.name.medium             # MEDIUM variant
car.names                   # [SHORT, MEDIUM, LONG] in a fresh list
car.name.for_style("LONG") # separate LONG-preferred string-like view

# Legacy APIs: car.short, car.medium, car.long, car.choose("LONG")
```

`car.name` is a `str` subclass and can be compared to plain strings. It is
constructed from the immutable three-variant `GameCarName` record. `.names`
returns a new list, so modifying the returned list never alters source data.
When a particular variant does not exist its attribute and list entry are
`None`; selecting an absent variant results in an empty string rather than a
name borrowed from another variant. `car.name.medium is None` distinguishes
that state from a present MEDIUM string.

An exact model-key lookup without a record returns `None` (no synthetic name).
`CarNameStyle` continues to accept uppercase/lowercase style names, and the
legacy `.choose(style)` continues to return an optional plain string.

## Existing read-only crew model

The existing `CrewMemberVehicle` model has raw `.model_key` and scalar stats.
It does not fetch or infer translated names. To bind a known translation source:

```python
# snap = services.get_crew_optional_snapshot() # separate authorized game read
named_snapshot = snap.with_translations(translations)  # no HTTP
vehicle = named_snapshot.members[0].vehicle
vehicle.name                 # MEDIUM, or None if model was not matched
vehicle.name.long            # LONG if a model was matched
vehicle.names                # [SHORT, MEDIUM, LONG]; [] if unmatched
```

Likewise `vehicle.with_translations(translations)` returns a modified copy
of an individual vehicle. Both operations are immutable, preserve the original
source snapshot, and reject non-translation arguments. A new translation set
*replaces* prior bindings; stale mappings cannot survive re-binding.

Other typed source models already expose attributes: crew member `.name`,
`.nickname`, `.season_crew_rp`, vehicle `.pp`, `.ep`, `.appearance`, and
appearance `.paint_id`, etc. Those fields have different meanings and do not
need a three-name structure. `VisualCodeName.name` continues to contain the
single source-backed cosmetic label; no invented variants are introduced.

## CLI reporting and privacy

`game_label_report(..., show_members=False)` publishes only source and match
counts, never private member names, exact car names, or cosmetic labels. With
explicit `show_members=True`, `member_labels[].car_name` remains the chosen
style string for backward compatibility. Dev9 additionally exposes
`member_labels[].car_names` as the three-element list, including missing
variant markers. The bulk report binds translations only in memory; it does
not add or change game requests. No raw IDs or player identities are printed
unless existing explicit privacy controls already allow that material.

## Evidence / limits

Dev8 decoded the operator-provided `Localisation_EN.ASTC.6312` game file;
Dev9 additionally exercised the attribute API against that exact file.
The complete asset is **not distributed** with the Python package.
Visual-code name *source schemas* still require separate native verification.
The experimental expanded GCC range and optional numeric-stat meanings also
remain candidates pending the planned combined live test. Published 0.7.0 is
unchanged.
