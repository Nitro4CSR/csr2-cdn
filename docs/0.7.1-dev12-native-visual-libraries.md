# 0.7.1.dev12 — observed Android ASTC visual library records

## Real-source evidence

Three **operator-provided** Android ASTC assets were decoded entirely offline:

| Source | Compressed bytes | Typed records | Record schema |
| --- | ---: | ---: | --- |
| `CarPaintLibrary.ASTC.1195` | 69,527 | 2,905 | ID, Name, UnlockLevel, CarPaintType, DiffuseTint, MetallicTint, six material float fields |
| `CarLiveryLibrary.ASTC.1042` | 25,462 | 1,452 | ID, NameID, CarLiveryType, four texture names, TileFactor, CashCost, OEM, F0, Shininess |
| `CarInteriorLibrary.ASTC.1139` | 39,698 | 2,170 | ID, Zone1Name, Zone2Name, two RGBA tints, InteriorTilingZone2, Origin, CashPrice |

Each asset is UnityFS version 8, Unity engine 2021.3.16f1, with one
Unity serialized-file version 22 node. The payload block uses **LZMA1** with a
five-byte properties header. Earlier CDN UnityFS tooling only decoded LZ4;
Dev12 extends that to bounded Unity LZMA1 blocks without a new dependency.

The field names above come from the actual embedded Unity type trees. All
6,527 decoded IDs are distinct **within their respective libraries**. IDs
are library-global and do not embed the car model key. The library importer
uses a `model_key='*'` fallback; an explicit model mapping overrides it.

Interior names are two separate zones. `visuals.interior.name` is the first
zone; `visuals.interior.names` preserves both in source order. Whitespace
(including an observed carriage return) is normalized in **display labels**;
we don't pretend a normalized value is byte-for-byte original.

## Public API

```python
from csr2cdn import load_visual_libraries_unityfs

visual_names = load_visual_libraries_unityfs([
    "CarPaintLibrary.ASTC.1195",
    "CarLiveryLibrary.ASTC.1042",
    "CarInteriorLibrary.ASTC.1139",
])

# Example: snapshot comes from an independently authorized crew read.
named = snapshot.with_visuals(visual_names)
car = named.members[0].vehicle
print(car.visuals.paint.name)
print(car.visuals.livery.name)
print(car.visuals.interior.name)
print(car.visuals.interior.names)  # Both zone names, if present
print(car.visuals.paint.code)  # Preserves the original game ID
print(car.visuals.paint.source_sha256)  # Local UnityFS provenance
```

Inspect without game requests:

```sh
python -m csr2cdn.visual_library_validation \
  --asset CarPaintLibrary.ASTC.1195 \
  --asset CarLiveryLibrary.ASTC.1042 \
  --asset CarInteriorLibrary.ASTC.1139
```

Add `--show-examples` to opt into up to three cosmetic labels per source.
The combined crew feature validation also accepts repeatable
`--visual-asset-bundle` arguments, avoiding hand-written mapping manifests.

## Boundaries

- The CDN asset database version is from the filename / supplied database;
  the loader fingerprints the **actual bytes** and doesn't claim to refresh
  them or determine whether newer versions exist.
- The decoder is scoped to these observed Android ASTC/Unity type-tree layouts.
  Unsupported future library schemas fail closed and should get updated tests.
- `High` is not used as an Android ASTC default or treated as interchangeable.
  iOS/platform-specific compatibility requires its own evidence and testing.
- IDs are directly typed in the asset library, but end-to-end selection in a
  live crew vehicle remains pending the planned authorized bulk test.
- This package contains only decoder code and synthetic tests; no copyrighted
  game asset is redistributed, and no game authentication is required here.
