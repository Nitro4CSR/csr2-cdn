# CSR2 0.7.0.dev6 — analysis of October 15 dev5 validation

## What the report establishes

- `0.7.0.dev5` passed 337 offline tests on Windows/Python 3.13, installed and
  built correctly. The report does not establish Linux or Python 3.9 CI.
- A historical event in local metadata yielded the four native leaderboard
  inputs and a requestable identifier; its time status was `elapsed`.
- The metadata-service probe succeeded but produced only one historical group,
  no active Championship Showdown candidate, and no standings read.
- Session setup produced an account-identity mismatch before a crew read.
  Without a sanitized *schema-level* confirmation of token interpretation,
  replacing or suppressing this check would be an unsupported change.
- Prestige Cup and legacy Showdown Leagues were not exercised in that run.

## Additional native evidence for missing live Showdowns

CSR2 6.8.0 native methods show a separate runtime event-data path:

1. `EventCommonMetadataDatabase.LoadMetadata` at RVA `0x3427ef8`
   calls `AssetDatabaseData.GetAssetsOfType`,
   `GetAssetAndMetadataIDList` and `LoadMetadataFromAssetBundle`.
   The `GetAssetsOfType` call passes numeric asset category `0x2f` (47).
2. `EventCommonMetadataDatabase.LoadMetadataFromAssetBundle` at
   RVA `0x342814c` calls `CSR2ClientMetadataAssetBundle.LoadMetadata`.
3. `ShowdownEventsDatabase.LoadFromModularEventMetadata` at RVA `0x342a33c`
   loops over incoming groups and appends groups whose `EventGroupName`
   is absent from the standalone container.

This **proves a client-side additional event source and a merge path**. It
neither proves which current event is present nor identifies the exact public
bundle code, payload schema, or network response. The existing metadata service
is therefore *not* an authoritative complete current event catalogue by itself.

## Code changes in dev6

- `modular_event_assets(database)` lists asset type 47 from any existing
  `AssetDatabase`, without making network requests or guessing bundle codes.
- `ShowdownDiscovery` accepts an optional authoritative, already-parsed runtime
  group source and merges it without modifying the standalone input.
- `--modular-groups-file` is an offline integration/testing input.
- The live-validation summary reports source-coverage limits and elapsed
  candidates without including account information or event names.
- Syntax and native-resolution tests remain offline. The default PlayerID-plus-
  Showdown-name API is unchanged.
- Authentication identity verification remains active; no fallback to an
  unrelated account, token mismatch bypass, save-game endpoint, or chat read
  was introduced.

## Still blocked before final 0.7.0

- Resolve **runtime event asset discovery**, download and decoding from the
  authoritative asset database and associated bundle contents, then merge
  those groups with correct timing and player/segment gates.
- Verify the actual live metadata payload and active Championship Showdown.
- Validate the session account-selection and token-claim interpretation using
  the account owner's environment, without logging tokens or raw responses.
- Perform authorized read-only crew and leaderboard requests, validate score
  units, ranking, pagination, and errors. Add Prestige Cup event discovery.
- Run the Windows/Linux by Python 3.9/3.13 CI matrix, then rebuild and publish
  only after successful live compatibility verification.

`0.7.0.dev6` remains **unreleased experimental code**. No production
compatibility or GitHub/PyPI publication is claimed.
