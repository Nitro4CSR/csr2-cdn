## Dev74 — Gacha configuration and aftermarket paint mutation guards (APK-only)

The CSR2 6.8.0 native code permits a runtime-guarded, **pre-setup**
`CarVisuals.ApplyGachaConfig` call that can append a paint ID, update the visual
selected index, refresh the paint and copy the chosen index back to the garage
car. `ForceUpdateOfCarPaint` conditionally invokes `AddAftermarketPaintsToCar`
only when the selected paint index is out of the current list bounds; the
callee checks membership before appending candidate IDs. These are **possible
static paths** only, not observed execution for the Tutorial Mustang.

```bash
python -m csr2cdn.dev74_gacha_paint_mutation \
  --apk CSR2_6.8.0.apk \
  --output dev74-gacha-paint-evidence.json
```

See [Dev74 technical notes](docs/DEV74_GACHA_AND_AFTERMARKET_PAINT.md).
Paint index 15 → ID 1323 remains a historical conditional candidate only;
paint index 0 and the actual car-local ordered paint list remain unresolved.
No production mapping change or authenticated gameplay request.

## Dev68 — Conditional loader paint-index and paint-ID override dispatch (offline)

The CSR2 6.8.0 APK's compiled `CarLoader` has separate override paths. The named
`carDetailsOverride` input passes from `CarLoader.LoadCar` via `CarLoaded` to
`SetupCarVisuals`. A non-sentinel override index calls `set_CurrentPaintIndex`;
if the index is `2147483647`, a valid paint-ID override instead calls
`SetPaintIDAddIfNecessary`. With no override object, both of those
**override-specific** calls are skipped; normal visual setup still runs. An
override call copies `CurrentPaintIndex` to the garage car.

The code **does not show** whether crew display uses CarLoader or supplies an
override. Existing static reconstruction of the Tutorial Mustang at index 15
produces conditional paint ID 1323 (Ford Dark Highland Green), **not** a
verified rendered ID. Paint index 0 remains unresolved. No resolver edit.

```bash
python -m csr2cdn.dev68_loader_paint_overrides \
  --apk CSR2_6.8.0.apk \
  --car-metadata-bundle CarMetadata.ASTC.1594 \
  --visual-bundle Ford_Mustang302_1970_common.ASTC.14 \
  --cache-zip endpoint-cache.zip \
  --source-catalog dev36-source-ids.json \
  --paint-index 15 --output dev68-evidence.json
```

See [Dev68 technical notes](docs/DEV68_LOADER_PAINT_OVERRIDES.md).
This diagnostic is offline and source-version pinned. User APK, Unity assets,
and private response cache are never packaged. Optional `lz4` is required for
UnityFS v8 assets.

# 0.7.1.dev62 — Milestone setup guards and cached unlockables

Dev62 adds an **offline, source/APK-pinned** diagnostic of the CSR2 6.8.0
`CarVisuals.Setup` → `SetupAftermarketLockedData` → `LockedCustomisationData.SetupMilestones`
route. It verifies that `Setup` calls the locked-customization initializer only when
`HasMilestonesForCar` is true and `IsTunerStarsCar` is false. `SetupMilestones`
reads its source milestone list at `this+0x20` and writes the prepared list at
`this+0x30`; `GetAllUnlockables` instead directly returns its populated field
at `this+0x28`. The crew's saved milestone level **50** is therefore not
verified to reorder the serialized `AllUnlockables` list.

```sh
python -m csr2cdn.dev62_aftermarket_milestone_guards \
  --apk CSR2_6.8.0.apk \
  --bundle Ford_Mustang302_1970_common.ASTC.14 \
  --source-catalog dev36-source-ids.json \
  --private-cache-zip endpoint-cache.zip \
  --paint-index 15 --output dev62-aftermarket-guard-evidence.json
```

The same conditional source-data replay still yields **index 15 → 1323**, Ford
Dark Highland Green. **This is NOT a production-verified crew paint mapping**:
we have not measured the two runtime predicates or proven the loaded runtime
component and list are unmodified. Paint `0` remains unresolved; the earlier
"Transparent" hypothesis stays withdrawn. No server calls or production resolver
changes. The APK, Unity bundle and private roster are not included.
See `docs/DEV62_AFTERMARKET_SETUP_GUARDS.md`.
