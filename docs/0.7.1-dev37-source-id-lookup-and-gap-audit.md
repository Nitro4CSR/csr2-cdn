# Dev37: Offline source-ID lookup and gap analysis

**Purpose.** Investigate individual suspected paint/interior/calliper numeric IDs and source-library numbering gaps using the **previously exported Dev36 public catalogue and matching summary**. No authenticated gameplay, public CDN requests or network calls are performed by this module.

## CLI

Run against the Dev36 catalogue and its matching summary. No original source binaries are needed for this analysis:

```bash
python -m csr2cdn.dev37_source_id_lookup \
  --catalog dev36-source-ids.json \
  --summary dev36-summary.json \
  --slot paint \
  --id 1000032 \
  --id 1000139 \
  --output dev37-paint-id-lookup.json \
  --gaps-csv dev37-numbering-gaps.csv \
  --catalog-csv dev37-source-catalogue.csv
```

Use `--slot all` (default), `paint`, `interior` or `calliper` to constrain a query. Use repeated `--id` values or `--ids-file suspects.txt` (one nonnegative decimal numeric ID per line; comment lines starting `#` permitted). Each number is checked exactly; the tool does not guess aliases or vehicle eligibility.

- Source match: reports source slot/library, exact label, additional source labels and category, **not** a verified in-game appearance.
- Absent: states the ID does not appear in any *selected* library. This does not mean it appears in the historical roster.
- Multiple attributes: reports them separately and explicitly does not call them an ambiguous cosmetic mapping.
- Same-attribute multiple records: reports every source without selecting a winner.
- Gaps CSV: one row per unoccupied number **between the minimum and maximum occupied ID in each individual library**. Never treat these gaps as roster evidence.
- Catalogue CSV: one row per original Dev36 source record; protect CSV cells that might be interpreted as formulas.

## Validation, limits and privacy

The CLI checks catalogue metadata, all six source names, slot/name/type constraints, record counts, duplicate (library, ID) pairs, and equality of the catalogue's source SHA-256 metadata against the Dev36 summary's stored values. This is **metadata consistency**, not a fresh SHA-256 verification of original source bundles. Source names and ID labels are public source evidence but not confirmed vehicle eligibility. Input size/query limits, no symlink inputs, exclusive writes and owner-only permissions where available reduce accidental disclosure or alteration. Outputs are opt-in and never overwrite files.

The module imports no HTTP clients and does not call any network endpoint. Production decoders, strict loaders, vehicle eligibility rules and existing trusted mappings are unchanged. The separate Dev36 tool remains available for a genuinely new public-source snapshot or for **saved** roster comparisons.

**Disposition:** Evidence-only investigation; not a release candidate and not proof that any of the original eleven missing roster IDs have been recovered.
